## 二、用户参与的 AIPM 训练流程

这次 part 2 **完整还原了 AIPM 标准协作流程**：

```
步骤 1：我（Claude）列 16 条 fallback 候选 + 期望 fallback 类别 + 测试意图
```

**关键洞察**：用户作为转行 AIPM 初学者，主动要求"锻炼人工核对能力"——
但人工核对的真正训练点不在"看 query 像不像真实"（这是直觉），
**而在"看实跑结果与预期是否一致"（这是数据驱动）**。

## 三、揪出的 5 个 scenario.py bug

| # | query 草案 | 期望 | 实际 | 根因 |
|---|---|---|---|---|
| #3 | `你好啊` | chitchat | ambiguous | chitchat 正则末尾 `[\s\?！？!~。.]*$` **不含中文语气词**"啊呀哈呢吧" |
| #4 | `这个系统是做什么的？` | chitchat | ambiguous | 自我介绍正则只覆盖"你是谁/介绍自己"，**漏"这个系统/本助手"类** |
| #7 | `怎么能让超容积率项目顺利过审？` | sensitive | normal | `怎么.{0,5}过审` 距离 5 不够（实际 12 字符）|
| #8 | `我想偷偷把幼儿园建在 280m 范围外` | sensitive | normal | sensitive 关键词集 **漏"偷偷"独立词**（只有 `偷.{0,3}做`）|
| #9 | `GB 50096-1999 ...` | deprecated | normal | regex `(?:93\|87\|99\|2002\|2006)` 在 "1999" 位置 0='1' 不匹配 |

## 四、修复实施

### 1. chitchat 末尾语气词
```python
# 加 "啊呀哈呢吧呦哟嘛" 进允许字符集
_TAIL = r"[\s\?！？!~。.啊呀哈呢吧呦哟嘛]*"
```

### 2. chitchat 自我介绍扩展
```python
# 加 "这|这个|该|本 + 系统|工具|助手|程序|AI|平台" 类
rf"^(这|这个|该|本)(系统|工具|助手|程序|AI|平台).{{0,10}}(是|能|做|帮|查|干).{{0,5}}\??$",
```

### 3. sensitive "过审"距离扩 + 独立 pattern
```python
r"怎么.{0,20}过审",  # 5→20
r"如何.{0,20}过审",  # 加 "如何" 路径
r"怎么.{0,20}过(检|查)",
r"顺利.{0,8}过(审|检|关)",  # 加 "顺利过 +审/检/关" 独立 pattern
```

### 4. sensitive "偷偷" 独立词
```python
r"偷偷.{0,15}(做|建|盖|搞|算|报|拿|放|做)",  # 加宽动词集
```

### 5. deprecated regex 加四位年份
```python
r"(?:1993|1987|1999|2002|2006|93|87|99)(?!\d)"
# 加全四位 + (?!\d) 防止前向数字误吞
```

## 七、AIPM 启示 35 · "评测集 → 系统 bug" 的双向反馈

W4 D2 启示 33 是单向：评测集质量提升 → 数字可信化（v2 → v3）
W4 D3 part 1 启示 34 是循环：评测集质量循环可信化（v3 → v3.1）
**W4 D3 part 2 启示 35 是双向**：

```
评测集设计 → 发现"看似合理"的 case
       ↓
实跑评测 → 暴露系统真实行为与设计差异
       ↓
要么修系统（方向 A，今天选的）→ 系统更稳健
要么改评测集（方向 B）→ 接受现状
       ↓
回归测试保证修复无副作用 → 整体进步
```

**核心**：评测集不是被动验证工具，而是**主动暴露系统盲点的探针**。
