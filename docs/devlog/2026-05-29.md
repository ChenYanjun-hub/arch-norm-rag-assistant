## 四、踩的坑

### 坑 1：Vite 8 + Tailwind v4 配置变了

- v4 已不用 `tailwind.config.js`/PostCSS plugin，改用 `@tailwindcss/vite` 插件
- 在 `vite.config.ts` 里 `plugins: [react(), tailwindcss()]`
- 在 CSS 用 `@import "tailwindcss";` 而非 `@tailwind base/components/utilities`

### 坑 2：Vite 默认监听 IPv6（::1）

- `curl 127.0.0.1:5173` 返回空，`curl localhost:5173` 才工作
- 原因：Vite 8 默认绑 :: 而 zsh 别名解析方式不同
- 启动加 `--host 0.0.0.0` 可强制 IPv4，本机开发可忽略

### 坑 3：FastAPI FileResponse 中文文件名爆 latin-1

- `HTTP/1.1 500 UnicodeEncodeError: 'latin-1' codec can't encode characters`
- HTTP header 默认 latin-1 编码，PDF 文件名含《》不行
- 修：RFC 5987 `Content-Disposition: inline; filename="ascii.pdf"; filename*=UTF-8''%E5%9F%8E...`
- ASCII 兜底名 + UTF-8 编码扩展名 双保险

### 坑 4：Reranker 选错包导致 ImportError

- 首版 import `from FlagEmbedding import FlagAutoReranker`（不存在）
- 正确 `from FlagEmbedding import FlagReranker`
- 教训：装新依赖前先 `pip show FlagEmbedding` 看版本，再查 docs

### 坑 5：Vercel hook 反复注入 "use client"

- 当前栈是 **Vite SPA**，不是 Next.js App Router，所有 `.tsx` 默认就是客户端
- hook pattern-match `src/components/**`、`pages/**` 误以为 Next.js
- 处理：每次 hook 提示直接跳过；CLAUDE.md B.1 已锁前端不上 Vercel

## 五、AIPM 视角的本日洞察（新增 3 条）

### 洞察 6：**设计 token 化是产品快速变体的杠杆**

今天改"同济蓝"主题只动了 12 个 CSS 变量（`--primary` / `--sidebar` 系列）。如果直接写 hex 在组件里，要改 50+ 处。

**对 AIPM 的启示**：在 PRD 阶段就要求设计稿用 design tokens 而非具体 hex 值。一句"用 tokens"的要求，能让后续主题切换 / 暗黑模式 / 客户定制成本从"重做 UI"降到"改 10 个变量"。

### 洞察 7：**原型→产品 的视觉差异：暗示 vs 显式**

设计稿用学术徽章风格的 logo，但本身没用任何具体高校元素。我做的"致敬版"也是：

- ✅ 圆形（基础几何，没有任何特定 IP 含义）
- ✅ 同济蓝（颜色非商标）
- ✅ 通用字符（"同"是常用汉字）
- ❌ 没复制具体校徽的舟楫/绕环/拉丁文等

**对 AIPM 的启示**：在向 AI / 设计师 brief 时要主动列"可借鉴的暗示元素"和"必须原创的具体造型"。AI 在没有明确边界时容易越线，PM 要先把边界画清楚。

### 洞察 8：**"可溯源"才是 RAG 产品和聊天机器人的本质区别**

W2 Day 2 加上 /api/spec 端点 + 前端 PDF 按钮后，整个产品的"AI 版规范法条数据库"定位才真正成立——用户可以**1 秒从 AI 答案跳到原文 PDF 的具体页**。

之前的 SSE + 引用卡只是"展示出处"；今天才是"可验证出处"。

**对 AIPM 的启示**：RAG 产品的差异化不在"能引用"，而在"引用能点击 → 跳到原文 → 用户能秒验证"。如果用户验证一条规范要 5 分钟（查 Google → 找 PDF → 翻页），那本质上就是个"聊天工具"。如果只要 1 秒，才是真正的"AI 法条数据库"。
