## 四、🎯 反直觉发现：OCR 修干净让 LLM 更敢编造

### D5→D6 翻转分析

```
修复 (D5 veto → D6 OK):   15 条
新触发 (D5 OK → D6 veto): 19 条
持续 veto:                23 条
两次都 OK:                59 条
```

19 条新触发中：
- **16 条（84%）是 dim7 编造**
- **11 条（58%）涉及 OCR 修过的 spec**（GB 50180-2018 6 条 + 其他 5 条）

### 机制解释

**chunks 修干净 → LLM 更"理解"上下文 → 更敢"补充说明"**

- 原 chunks 含"坏境/贼市/改著"等错字时，LLM 对上下文有保留 → 更保守
- 修后 chunks 清晰，LLM 反而更"放心"加 chunks 外的"完整化"补充

### 启示 54 候选 · 数据质量提升 ≠ 产品质量提升

> 修 chunks OCR 错字让 RAG 输出**编造问题更明显**（dim7 -5.2pp）。
> 这反过来证明启示 52："补充说明"是 LLM 训练惯性，跟 chunks 质量无关。
>
> **等价表述**：底层数据更干净 → LLM 更敢自由发挥 → 编造模式更显眼。
> 数据清洁是必要不充分条件，必须配合后处理（post_filter）才能根治 dim7。

## 七、AIPM 启示候选

### 启示 54 候选 · 数据质量 ↑ ≠ 产品质量 ↑

数据清洁是必要不充分条件。OCR 修干净反而让 LLM 编造更猖（dim7 -5.2pp），印证启示 52：要根治"补充说明"惯性必须 post_filter 后处理。

**等价表述**：在 LLM 输出层，干净的数据让"训练惯性"更显眼 — 因为模型更敢自由发挥。

应用：
- 数据治理与 LLM 行为治理是两个层面，缺一不可
- W6+ 优先级：post_filter 集成 > OCR 修复（虽然两者都做）
- 答辩 deck 应该坦诚说："OCR 修复让我们更精准识别 LLM 训练惯性问题"
