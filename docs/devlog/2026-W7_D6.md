## 二、调试事件 ·「发送后不显示」假 bug

### 症状

用户在自己浏览器发问 → 卡"回答中…"，答案区只有闪烁光标、无 token、右栏 0 引用。**与 W6 D4 那次 SSE CRLF bug（启示 61）症状一模一样。**

### 排查（分层隔离，不凭症状下结论）

| 隔离层 | 手段 | 结果 |
|---|---|---|
| **后端协议** | `curl -N POST /api/chat` 看原始字节 | ✅ SSE 健康：5111 字节、`event: token\r\ndata:"阻火墙"` 正常流、CRLF 正确 |
| **后端生成** | 看 backend log | ✅ 用户那次 15:13:21 已 `stream done 135 tokens` |
| **前端代码** | 干净预览标签页跑同一 query | ✅ 完整渲染（TTFT 751ms） |
| **浏览器状态** | 剩下的就是它 | ❌ 用户标签页连接断裂 |

### 根因（我的操作导致）

我先用 Bash 起了**第一个 Vite**（用户标签页连的是它）→ 为截图，我 **kill 了它、在同端口 5173 换成预览托管的 Vite** → 用户标签页连在被杀的旧 server 上，SSE 响应流喂不进页面（请求能到后端、响应回不来）→ 用户连点 3 次都卡（后端日志见 3 次请求，前 2 次被 abort、第 3 次生成成功但前端没收）。

### 修复

**硬刷新（Cmd+Shift+R）** 重连当前 Vite 即可。后端、前端代码均无 bug。

### 与启示 61 的关键对比

| | W6 D4（启示 61） | W7 D6（本次） |
|---|---|---|
| 症状 | 发送后不显示 | 发送后不显示（**一模一样**）|
| 根因 | **真 bug**：SSE CRLF 解析 | **环境假象**：dev server 被换 |
| 定位 | hex dump 发现 `\r\n` | 分层隔离（curl/净标签页）|
| 修复 | 改 apiClient 解析 | 硬刷新 |

→ **相同症状，根因完全不同。** 凭"哦又是 SSE bug"直接改代码 = 浪费时间改没坏的东西。

## 三、🎓 启示 68（详见 AIPM v6.7）

**相同症状 ≠ 相同根因；用分层隔离快速定位真/假 bug。**
- 后端 curl 隔离协议层、净标签页隔离代码层 → 剩浏览器/环境状态
- 别在用户开着标签页时把 dev server 从底下换掉（kill+restart 同端口）= 制造幽灵 bug
