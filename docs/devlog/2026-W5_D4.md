## 三、改动 3 · pipeline dangling 监控

**文件**：`backend/app/rag/pipeline.py`

- 流式 token 边收边 yield，末尾扫 `\[(\d+)\]` 引用号
- N > len(chunks) 视为 dangling，logger.warning 输出
- emit 新 `metadata` 事件携带 `{dangling_count, n_citations_in_answer, n_chunks_available}`

**已知 regex 偏差**：`[2010]` 这种年号脚标会误匹配 — 1 条 false positive。W5 D5 修。

## 九、AIPM 启示候选（3 个新）

### 启示 50 候选 · 评测工具的故障是评测结论的隐藏变量

W5 D4 看似 -2.6 分实际 +1.5 分，差距全在 5 条 API err 被工具误判 0。

**等价表述**：评测工具的失败处理必须保守（**跳过 ≠ 判 0**），否则会污染结论方向。

应用：
- run_quality_eval.py API err 处理：`d3=d4=d5=d7=0` → 跳过该条不计入分母
- 加重试机制 + 显示 n_eval / n_attempted 比例

### 启示 51 候选 · prompt 约束的"直接命中 vs 间接漂移"

W5 D4 4 条约束效果差异：
- 约束 1（[N]范围）→ dim3 +2.5pp（**强直接命中**）
- 约束 4（不联想）→ dim5 +3.3pp（间接受益）
- 约束 2（不补充）→ dim7 ≈0pp（**直接命中但无效**）
- 约束 3（强条标识）→ dim7 ≈0pp（直接命中但无效）

**等价表述**：prompt 约束只能根治"明显违反规则"的 case；LLM 的"训练惯性"（如"完整回答"）prompt 写得再严也很难根治，需要**后处理硬剥离**或 **few-shot 反例**。

### 启示 52 候选 · "补充说明"是 LLM 难以根除的训练惯性

W5 D4 约束 2 修复率 ~0%。即使写 "禁止补充说明""任何补充说明小节"等强烈语言，LLM 仍然会输出"另注""说明""注意"等节并加 chunks 外内容。

**等价表述**：要根治这类问题，**最有效是后处理代码**层面 strip 整段，而不是再写更狠的 prompt。
