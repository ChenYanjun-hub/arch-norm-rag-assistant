## 六、AIPM 启示 34 · "评测集是循环可信化的"

W4 D2 学到"评测集决定数字可信度"。W4 D3 进一步：**评测集的可信化是循环过程**。

每跑一次评测，会暴露新一轮"评测集本身的瑕疵"：
1. v1 (50 条) → 跑评测发现 16 条 spec 不在库
2. v2 (修 spec) → 跑评测仍发现 strict 偏低
3. **v3 (改 16 条 spec + 转 fallback) → 跑评测发现 14 条 expected_clause 错位**
4. **v3.1 (修 14 条 clause) → strict 翻倍**
5. 预期 v4 (扩 20 条新场景) 会再暴露新瑕疵

**做评测集就像剥洋葱**——每一层修订都让数字更接近真实。

**实操经验**：不要追求"一次性写完美评测集"，应该**先快速跑 + 看错例 + 局部修**，循环 3-5 轮才能稳定。
