## 二、做了什么

### A 路径 · 扩 reranker 候选 20 → 30
- `config.py` 加 `RERANK_CANDIDATE_K`（默认 30）
- `pipeline.py`/`run_eval.py` dedup 后保留 30 条给 reranker
- 预期救 Q003/Q019/Q027（在 top-21/29/38）

### B 路径 · 增强 reranker passage
- `reranker.py` 加 `_build_passage()` 辅助函数 + `passage_format` 参数
- 3 种格式：
  - `text_only`（W3 D2 默认）
  - `clause_text`：`"{clause} {text}"`
  - `rich`：`"<规范>{spec_name}</规范> <条文>{clause}</条文> {text}"`
- 默认 `clause_text`
- 预期救 Q010（在 reranker 输入 rank 10 但被排出 top-5）

### 评测 · 4 组合矩阵

| config | Hit@5 strict | Hit@5 loose | 时延/条 | 评价 |
|---|---|---|---|---|
| **baseline** (ck=20, text_only) | 2.6% | **50.0%** ⭐ | 4.9s | 最佳 |
| A only (ck=30, text_only) | 2.6% | 47.4% (-2.6) | 6.4s | ❌ 劣化 |
| B only (ck=20, clause_text) | 2.6% | 47.4% (-2.6) | 4.8s | ❌ 劣化 |
| A+B (ck=30, clause_text) | 2.6% | 50.0% (= ) | 7.2s | ⚠️ 持平 + 50% 时延 |

## 三、失败根因（最重要）

### 表面：4 个组合无一改善 strict / loose

- **Strict 永远 2.6%**——4 组合中没有任何一条 row 状态变化
- A 单独：扩候选稀释 reranker 输入信号 → 劣化 loose
- B 单独：passage 格式变化让 reranker 排序略变化，恰好把某个临界 case 拉下来 → 劣化 loose
- A+B：两个劣化效应彼此抵消，但 strict 仍 0 改善

### 深层：诊断假设对了，改造假设错了

W3 D4 是 **"假设链失效"** 的典型案例：

| 诊断假设 | 实测 | 改造假设 | 实测 |
|---|---|---|---|
| Q003/Q019/Q027 在融合 rank 21-38 | ✅ 正确 | 扩 ck 30 让它们进 reranker → reranker 排前 5 | ❌ reranker 仍排到 6-30 |
| Q010 在 reranker 输入 rank 10 | ✅ 正确 | clause 拼进 passage 给更多锚点 → 排进 top-5 | ❌ rank 几乎不变 |

**诊断**告诉你哪里有问题，但 **不能保证**你提出的改造方案能解决——尤其当 reranker 是黑盒模型时。

### 最深层：reranker 是模型瓶颈

BGE-Reranker-v2-m3 是预训练 cross-encoder，没在中文规范数据上微调。它对：
- "办公建筑的耐火等级" ↔ "5.1.2 楼板耐火极限 + 5.1.3 ..." 的关联度
- "幼儿园服务半径" ↔ "5.0.3 配套设施分级" 的关联度

判断不够精准。这是**模型能力上限**，不是 parameter tuning 能解决的。

CLAUDE.md 锁定 reranker = BGE-Reranker-v2，不能换。所以 strict 2.6% 在当前架构下是**硬天花板**。

## 六、AIPM 启示（W3 D4 收获最深）

### 启示 25 · "诊断假设 ≠ 改造假设"

W3 D4 暴露的最深问题不是"实验失败"，而是 **诊断到位 ≠ 改造方案就有效**。

诊断告诉你 "Q010 在 reranker 输入 rank 10"——这是事实。
改造假设说 "改 passage 格式 → reranker 排上来"——这是 **未经验证的因果推断**。

**AIPM 必须分离两层**：
1. 诊断层（事实，可验证）
2. 改造层（假设，需小样本验证）

**正确做法**：诊断完成后，**先在 1-2 个 case 上验证改造能否真的解决**，再扩到全量评测。

### 启示 26 · 黑盒模型的"参数调优天花板"

reranker / embedding / LLM 都是预训练黑盒，参数调优（输入格式、temperature、top_k）的有效性**有限且不可预测**。

工程视角的 4 层应对：
1. **参数调优**（最便宜，效果上限 10pp）
2. **prompt engineering** / 输入工程（中等，效果 5-20pp）
3. **微调 fine-tuning**（昂贵，需要标注数据，效果 20-50pp）
4. **换模型 / 自己训练**（最贵，效果最高）

W3 D4 我们做了第 1 层，撞天花板。**当前架构下接受 strict 2.6% 是模型物理极限**，要解锁必须升到 3-4 层（但 CLAUDE.md 锁定不能换）。

### 启示 27 · "连续失败" 的纪律

W3 D3 失败、W3 D4 失败、连续两天 0 进展，工程师容易：
- 急躁：随便加路径试试
- 放弃：转向别的看似简单的事
- 自我怀疑：是不是我哪里搞错了

**正确处置**：
1. 立刻停下来 reconcile（连续失败说明假设链有系统性问题）
2. 重新审视目标可行性（strict ≥ 30% 是否本就不可能？）
3. 接受 baseline，转攻其他能进步的维度（工程债 / 体验 / 评测集质量）

W3 真正的胜利不是"涨数字"，是 **学到"strict 2.6% 是当前架构的物理上限"**——这才是 AIPM 视角的成果。

### 启示 28 · "保留代码 + env flag" 的 W3 D3 处置成为方法论标准

W3 D3 学的"保留代码 + 默认关 + 文档解释"，W3 D4 立刻复用：
- `RERANK_CANDIDATE_K` env（默认 20，env 翻 30）
- `RERANK_PASSAGE_FORMAT` env（默认 text_only，env 翻 clause_text/rich）
- `_build_passage()` 函数完整保留

未来换 reranker 模型时，3 种 passage 格式可以**当场重新评估**，不需要重写代码。**这就是失败实验的复利**。
