## 五、🎓 启示 63 候选 · LLM 不会真心 self-doubt ⭐⭐

W7 D2 实证：

| Judge v2 prompt 设计意图 | 实际行为 |
|---|---|
| "不确定时给 1 分（避险）"约束 | confidence=hi **100%** — 从不标 mid/lo |
| 5 条 self-warning 约束 | LLM 仍然偶尔造错字（如 chunks 错字反向误判）|
| "对照 chunks 实际文本判分" | 部分判分仍像 v1 凭印象 |

**机制解读**：

LLM 训练时被强化为"自信回答"，prompt 加 "self-doubt" 类指令几乎无效。
即使 prompt 明确说"不确定时给 1 分 + 标 confidence=lo"，LLM 仍然 100% 给 hi。

**等价表述**：

> "用 LLM 校验 LLM" 时，self-doubt 类 prompt 指令的边际效益接近 0。
> LLM 不会真心承认"我不知道"，会强行做判断。

**应用**：

- 验收 LLM Judge 时不要靠 confidence 字段（无效信号）
- 真正的 calibration 必须靠**多次跑取交集**（启示 53）或**人工抽样核对**
- 如果想让 LLM 真 self-doubt，必须 fine-tune，不能靠 prompt

## 六、🎓 启示 64 候选 · chunks 质量是评测可信度的天花板 ⭐

W7 D2 发现 chunks 错字反向误判 LLM 正确答案的 5 个例子：

| QID | chunks（错）| LLM answer（对）| Judge 错判维度 |
|---|---|---|---|
| Q003 | "150000~100000"（表 3.0 OCR 错）| "50000~100000" | dim5=0 |
| Q033 | "游患"（OCR 错）| "游憩" | dim4=0 |
| Q038 | "0.50m"（漏单位）| "0.50m²/人" | dim5=0 |
| Q101 | "8.0m7人"（OCR 错）| "8.0 m²/人" | dim5=0 |
| Q128 | "每 100m"（漏单位）| "每 100m²" | dim5=0 |

**机制**：Judge 严格按 chunks 字面判 → chunks 错字时 LLM 写对反而被错杀。

**启示 49 (W5 D3) 的延伸实证**：
- 启示 49："PDF OCR 是隐藏的评测干扰项"
- 启示 64："**chunks 质量是评测可信度的天花板** — 不修 chunks 错字，dim4/dim5 上限就被锁死"

**应用**：

- 评测分上限 = chunks 准确率
- 想让 dim4/dim5 真正达 100% → 必须先做 chunks OCR 二轮校对
- 单纯改 Judge prompt 不能突破这个天花板
- 这也是为什么 W7 D2 即使 Judge v2 改进，dim5 仍然持平（chunks 错字限制）

**与启示 54 联动**：W6 D1 "数据质量 ↑ ≠ 产品质量 ↑" 是说 OCR 修后 dim7 反降（LLM 编造更猖）。
启示 64 是另一面："chunks 错字让 Judge 错杀 LLM 正确答案" — 数据质量低**确实**影响评测可信度。
两个启示一起看：**数据质量是评测可信度的必要条件，但不是产品质量提升的充分条件**。
