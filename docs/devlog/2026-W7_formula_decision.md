# W7 · 公式块渲染：诊断后决定「不渲染，改做守卫」— 启示 90

**结论**：⭐ 原型里有漂亮的公式块（`L = H · i` + 图例）。动手前先查语料——
**10785 条 chunk 里只有 1 条 `type=formula`，而且那一条也是 OCR 垃圾**。
公式在 PDF 提取中被普遍损坏，渲染它等于把乱码包装得像模像样，直接违红线 1/2。
于是**不做渲染**，改做诚实的守卫：含公式的条文打「含公式·查原文」标记。
沉淀 **启示 90**（设计稿画的是理想数据，先验证数据再实现视觉）。

---

## 一、诊断：公式在语料里是什么状态

分块规则写着 `formula_separate: True`，理论上应产出独立公式块。实测：

| chunk type | 数量 |
|---|---|
| clause | 8033 |
| appendix | 1941 |
| table | 810 |
| **formula** | **1** ← 而且是 OCR 垃圾 |

再查公式是否以文本形式混在 clause 里——**在，但全是坏的**：

| 实际 OCR 文本 | 问题 |
|---|---|
| `AADT= (4.5.4)` | **等号右侧整段丢失** |
| `E-B2FK×100% C= (13.4.2-1)` | 字符顺序错乱 |
| `PQI=T×am×RQI+RCIXa` | 变量错认（`RCIXa` 应为 `RCI×a`）|
| `FCI=100 DP,×a a=3.0w=5.5w+3.5 0` | 数字符号混乱 |

**结论：渲染无米之炊。** 更糟的是——把损坏公式渲染成漂亮的公式块，
会让用户以为那是准确公式，**这比不渲染更危险**（红线 1 不编造 / 红线 2 引用精确）。

## 二、改做的事：含公式守卫

不渲染公式，而是**标记 + 引导看原文**：
- 检测信号（保守口径）：`按下式计算 / 按下列公式计算 / 应按下式 / 式(x.x.x)`
- 实测命中 **109/10785（1.01%）**，抽样零误报
- 引用卡加徽章「含公式·查原文」，tooltip 说明"公式在 PDF 提取中易损坏，摘引可能不完整"
- **导出报告同步标注**——否则交付物丢了这条风险提示

## 三、🎯 实测恰好印证了必要性

用「路面行驶质量指数 RQI 应如何计算？」实测，徽章正确出现（5 条引用只有 `CJJ 36-2016 4.5.2` 被标，无误标）。
更关键的是这一条的对照：

| | 内容 |
|---|---|
| chunk 原文（OCR）| `路面行驶质量指数(RQI)应按下式计算: 1 ×No1-4.98-0.34×R1 (4.5.2)` |
| 模型答案 | `RQI = 4.98 - 0.34 × IRI` |

**模型没有逐字引用，而是从乱码里"还原"出了一个干净公式。**
这次看着合理，但它同样可能自信地重构出一个**错的**——这正是公式类幻觉的典型形态。
「含公式·查原文」就是针对这个的守卫。

> （深圳前海T3地块限定了 DB31T+GB50067，而 RQI 在 CJJ 36-2016）。

## 四、🎓 启示 90 · 设计稿画的是理想数据，先验证数据再实现视觉 ⭐

原型里的 `L = H · i` 公式块很漂亮，但那是设计师**假设数据是干净的**画出来的。
真实语料里公式已被 OCR 毁掉——**照着设计稿实现，产出的会是"精美的错误"**。

**对 AIPM 转行的启示**：
- **拿到设计稿先问"这个视觉需要什么数据支撑？我有吗？"** 视觉可以先行，但上线前必须回答这个问题。
- **渲染质量会放大数据质量的欺骗性**：同样一段乱码，纯文本显示时用户能看出不对劲，
  排进公式块反而显得权威。**呈现越精致，对数据质量的要求越高。**
- 这与 A 层"国标优先 boost"是同一类判断：**先诊断，根本条件不成立就不写那行代码**，
  但要给出诚实的替代方案，而不是简单说"做不了"。
