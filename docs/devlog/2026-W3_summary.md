## 🔬 4 次实验复盘

### D1 · retriever dedup ✅ 微效

- **目标**：修 chunker `_dN` 后缀让 text 重复的问题
- **数字**：top-10 strict +2.6pp（top-5 不动）
- **价值**：排除"OCR 是主因"的错误假设，节省后续 3-4h
- **洞察**：14-16（诊断诚实 / "改了不涨"也是成果 / 召回与精度是两条赛道）

### D2 · Query 改写 + RRF 融合 ✅ 真正涨数字

- **目标**：用 LLM 把 1 query 扩成 3 变体攻 BGE-M3 语义偏
- **数字**：Hit@5 loose **47.4% → 50.0%（+2.6pp）**，**规划域 +7.7pp**，**显性事实 +5.6pp**
- **代价**：时延翻倍 3.4s → 6.8s/条
- **价值**：W3 唯一数字涨幅来源
- **洞察**：17-20（正确归因 / 不为难病在别处的指标 / 工程债立刻记账 / 示例工程 > 指令工程）

### D3 · Hybrid 检索（BM25 + 向量）❌ 失败

- **目标**：BM25 补 BGE-M3 在专业术语精确匹配的弱项
- **数字**：Hit@5 loose -2.6pp，**规划域 -7.7pp**（W3 D2 涨的全跌回去）
- **根因**：评测集偏"问数值合规"型，BM25 召回"含数值的非答案条款"挤掉真答案
- **处置**：默认关 + env flag 一键启用 + 代码完整保留 + 详细失败日志
- **洞察**：21-24（"改了反而劣化"更宝贵 / 数据驱动决策极端版 / 失败要诚实记录 / "保留代码+默认关+文档"标准处置）

### D4 · Reranker 调参（候选 + passage）❌ 失败

- **目标**：扩 candidate_k 20→30 + passage 加 clause 锚点，攻 strict 2.6%
- **数字**：4 组合 strict 全部 2.6% 不动
- **根因**：BGE-Reranker-v2-m3 模型黑盒，参数调优无法解锁；CLAUDE.md 锁定模型不能换 = **物理上限**
- **处置**：默认值回滚到 baseline，代码 + env flag 保留
- **洞察**：25-28（诊断假设 ≠ 改造假设 / 黑盒模型的"参数调优天花板" / "连续失败"的纪律 / "保留代码+env flag" 成方法论标准）

### D5 · K 完整版兜底（8 类全覆盖）✅ 完成

- **目标**：补 W2 D1 留的 5 类 fallback（sensitive / deprecated / ambiguous + INPUT_EMPTY/TOO_LONG 走 fallback）
- **数字**：scenario 识别 26 case **100% 通过**
- **价值**：从"3 类能答"变"8 类知道什么不答" —— 产品边界感
- **洞察**：29-32（"礼貌拒答"是 AI 产品核心 / 优先级链是兜底设计核心 / 分段判定 > 单一阈值 / TODO 是技术债的可见性）
