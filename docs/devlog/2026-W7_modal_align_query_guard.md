# W7 · 修 align_modal_verbs 篡改用户提问 — 启示 88

**结论**：⭐ 强制性用语高亮上线后，**当场照出一个潜伏的治理 bug**：
`align_modal_verbs` 把答案里**引述用户提问**的那句量词也"校正"了——
用户问"服务半径**不应**大于多少米"，答案被改成"服务半径**宜**大于多少米"，读起来像助手听错了问题。
为守红线 3 而生的后处理器，在错误语境下自己改坏了量词。
修法：传入 query，保护"引号内 + 与 query 高度重合"的片段。
**阈值 0.90 是在 1802 条存档答案上实测出来的，不是拍脑袋**。沉淀 **启示 88**（治理组件也有作用域，越界即伤害）。

---

## 一、bug 现场（可见化的副产品）

刚做完"强制性用语分级高亮"，第一条实测查询就看到琥珀色的「宜」出现在一个奇怪的位置：

| | 内容 |
|---|---|
| LLM 原始输出 | 未查询到"…服务半径**不应**大于多少米"的直接依据 ✅ 忠实引述用户问题 |
| 后处理之后 | 未查询到"…服务半径**宜**大于多少米"的直接依据 ❌ **篡改了用户的提问** |

`metadata.modal_verb_corrections = 2`，确认是 `align_modal_verbs` 干的：
它按 chunks（"服务半径宜为300m~500m"）把"不应"对齐成了"宜"——
但**那一处不是在陈述规范，是在复述用户的问题**。

> 这是启示 85（可见化会反向暴露问题）的现场复现：这个 bug 之前一直在，
> 只是没有高亮时没人会注意到那个"宜"字不对劲。

## 二、修法与两次收紧

**思路**：给 `align_modal_verbs` 传 `query`，跳过"引述用户提问"的片段（只缩小作用域，不扩大）。

**判定条件（双条件，缺一不可）**：
- 在**引号内**（"…" / 「…」）
- 与 query 的相似度 ≥ 阈值（`difflib.SequenceMatcher`）

单看任一条件都不行：
- 只看相似度 → 误伤"答案恰好与提问用词相同的规范陈述"
- 只看引号 → 答案引用**规范原文**也带引号，那些恰恰**需要**对齐

### ⚠️ 第一版阈值 0.6 差点造成更坏的后果

在 1802 条存档评测答案上量影响面，发现 **4.4%（79 条）受影响**，
逐条看才意识到：**绝大多数不是"引述提问"，而是"引用规范原文"**
（如问"分车绿带、行道树绿带的造型树限制" → 答案引用原文"…不应采用造型树"，
用词自然与提问重合）。若答案在引号里**误引**了原文，那正是红线 3 该校正的，
我的守卫会把它挡住 —— **修一个 bug，造出一个更危险的 bug**。

### 用数据定阈值（14 条候选的相似度分布有干净断层）

| 相似度 | 类型 |
|---|---|
| **0.98** | 唯一一条**真·引述用户提问**（Q001）|
| **≤0.79** | 其余 13 条全是**引用规范原文** |

取 **0.90** 恰好切在断层上。方向上**宁可漏保护、不可误保护**：
误保护会拦下红线 3 的量词校正（有害），漏保护只是退回原行为（无新增伤害）。

## 四、🎓 启示 88 · 治理组件也有作用域，越界即伤害 ⭐

**`align_modal_verbs` 的职责是"让答案里**陈述规范**的量词与原文一致"，
但它的实现没有"作用域"概念——它对答案里**所有**量词一视同仁，
于是把"复述用户问题"的量词也改了。**能力正确，作用域错误，结果就是伤害。**

**对 AIPM 转行的启示**：
- **定义一个自动化规则时，必须同时定义它的作用域**："改什么"和"**在哪里不改**"同样重要。
  尤其这种为守红线而生的强制规则，越界时造成的正是它本要防止的那类错误。
- **修 bug 时的第二次风险最容易被忽略**：我的第一版守卫（阈值 0.6）看着修好了真 bug，
  实则会挡住 13 条合法的红线校正——**如果不去量影响面，我会带着"修好了"的错觉上线**。
- **阈值要用数据定，不要用直觉定**。0.6 是我拍的，0.90 是 1802 条样本里的断层给的。
  面试金句：*"我修一个后处理 bug 时，第一版阈值差点让它挡住 13 条合法的红线校正——
  我是在 1802 条存档答案上量了影响面，才发现分布有个干净断层，把阈值定在那里。"*
