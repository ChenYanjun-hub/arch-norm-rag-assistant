## 二、架构决策

### 2.1 单一真源 + 派生选择器（避免双账本 bug）

旧 store 只有一个 `messages: ChatMessage[]`（单会话）。改造为：

- **真源**：`conversations: Conversation[]`（每段会话含完整 `messages` + `title/createdAt/updatedAt`）+ `activeId`
- **派生**：`messages` 不再单独存，组件改用 `useActiveMessages()` 选择器从当前会话取
  - 稳定空数组常量 `EMPTY_MESSAGES`：无 activeId 时返回它，避免每次 render 生成新数组触发无谓重渲染
- 流式 `patch` 直接更新 `conversations` 里当前会话的目标 assistant 消息

> 为什么不留两份（messages 镜像 + conversations 归档）：双份必然要手动同步，迟早出现"视图和归档不一致"的 bug。单真源 + 派生最稳。

### 2.2 持久化只在"回合边界"落盘（不逐 token 写）

- 没用 zustand `persist` 中间件——它默认**每次 state 变更都写 localStorage**，流式逐 token 会触发上百次同步 `setItem`（序列化整个 conversations），是真浪费
- 改为手写 `loadPersisted()` / `savePersisted()`，只在 **done / error / 切换 / 删除 / 新建** 这些回合边界调用
- 内存态逐 token 更新（供 UI 实时渲染），localStorage 只在边界落一次——两者解耦

### 2.3 刷新卫生（sanitize）

载入时清理上次未完成的流式残留：
- `streaming: true` → 一律置 false（避免刷新后卡着闪烁光标）
- 空的 assistant 气泡（无 content 无 error）→ 丢弃
- `activeId` 指向的会话若已不存在 → 置空（回空态）
- 全程 try/catch：localStorage 不可用（隐私模式/配额）→ 退化为纯内存态，不阻塞 UI

## 三、交互

- 侧栏「历史会话」：真实计数 + 列表（💬 + 标题省略号 + hover/激活显 × 删除）
- 点历史项 → `switchConversation`（纯前端状态切换，瞬时）
- × → `deleteConversation`（删非激活项不打扰当前视图；流式中禁删）
- 「新建对话」（侧栏 + 顶栏按钮 + ⌘N/Ctrl+N）→ `newConversation`：回空态，**首次发送才真正建会话**（避免空会话堆积）
- 标题取首条用户问题前 24 字；新会话置顶

## 四、🎯 实测（全链路 · preview 驱动）

| 场景 | 结果 |
|---|---|
| 发首问（幼儿园服务半径）| 答案 grounded（保留"宜为300m~500m"未编"不应大于"）+ 3 追问 + 侧栏出现 1 条激活历史 + localStorage 落盘 ✅ |
| 新建对话 + 发第二问（防火墙）| 回空态→建第 2 会话；侧栏 2 条、新者置顶并激活 ✅ |
| 切回旧会话 | 正文/追问/引用/激活高亮整体换回幼儿园会话；activeId 落盘 ✅ |
| 刷新页面 | 2 会话恢复、上次激活者回显、无卡死流式态 ✅ |
| 删除非激活会话 | 该项移除、当前视图不受扰、localStorage 同步 ✅ |
| 追问 chip（同会话内）| 追加到**当前**会话（不另建）、回合数 2 / 消息 4 ✅（V2-1/V2-2 无回归）|
| 激活项样式 | `--sidebar-soft` 底 + 白字 + 左侧 amber 竖条 ✅ |

**回归**：`tsc -b` 通过；Chat.tsx 是 store 唯一消费者，无测试引用旧 API。

> 排查花絮：preview 控制台累计 64 条 `<ChatPage>` 告警一度疑似新 bug，经"reload 后计数不涨 + 现挂 hook 跑全路径 0 捕获"证伪为**上段会话遗留缓冲**（→ 启示 73）。
