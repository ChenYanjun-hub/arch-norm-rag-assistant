# W7 · 工具调用 Agent（ReAct / function-calling）— 启示 84

**结论**：⭐ agent 深化 ③：给 agent 三个确定性工具（目录导航 / 精确条文定位 / 现行状态），
用 DeepSeek function-calling 让它自己判断调哪个。**攻的是向量检索天生弱的"查表/元信息"类查询。**
实测四类查询全部路由正确（三类查表调对工具、内容类正确回退 RAG）。
沉淀 **启示 84**（不是所有问题都该丢给向量检索；以及"集成顺序"本身是 agent 架构的一部分）。

## 一、诊断：向量检索的能力边界

有三类查询，向量检索**天生弱**——它们不是"语义相似"问题，是"精确查表 / 元信息"问题：
- **目录导航**："你收录了哪些消防规范？"（要的是清单，不是某条原文）
- **精确条文定位**："GB 50180-2018 第 5.0.3 条原文是什么？"（exact-match，向量会召回"语义相近"的邻条）
- **现行状态**："GB 50016-2014 还有效吗？"（元信息，不在 chunk 正文里）

给 agent 工具去查，比让向量联想准——这正是 tool-use 的适用场景。

## 二、构建

- `services/spec_tools.py`：3 个确定性工具（`list_specs` / `lookup_clause` / `check_spec_status`）
  + function-calling schema。数据源 chunks JSON（Qdrant-free，模块级缓存）+ spec_status 服务。
- `core/prompts.py`：tool-agent system prompt（含"内容类不调工具"的判断示例）。
- `rag/tool_agent.py`：**多轮 ReAct 循环**（每轮都带 tools）+ 工具执行 + 结果喂回。
- `pipeline.py`：前置路由（默认关）——命中工具则作答返回，未命中回退常规 RAG。
- 单测 11 条（工具行为 + schema 一致性），全套 98 测试通过。

## 三、🎯 两个实测踩坑（都靠先测发现）

**坑 1：二次调用不带 tools → 模型把 tool_call 当文本吐出来。**
第一版是"单轮 + 拿结果再问一次"，第二次调用没传 `tools`，模型想调第二个工具时
直接把 `<｜｜DSML｜｜tool_calls>...` 当正文输出，污染答案。
**修复：改成多轮 ReAct 循环，每轮都带 tools**，直到模型不再调工具才收尾。

**坑 2：集成顺序错 → 工具查询被场景识别提前拦截。**
"你收录了哪些消防规范"被 `detect_scenario` 判成 **ambiguous**（模糊提问），
在 tool-agent 之前就走了兜底——工具根本没机会跑。
**修复：把场景识别拆成两段**——
- **硬短路**（空/超长/敏感/作废）：红线相关，最先拦，不给任何 agent 机会；
- **软兜底**（闲聊/超范围/模糊）：延后到 tool-agent 之后，工具没接住才兜底。

回归验证（6 类）：目录/条文查询走工具 ✓、内容查询走 RAG ✓、闲聊/超范围/敏感兜底完好 ✓。

## 四、🎓 启示 84 · 工具是能力边界的补丁；集成顺序是架构的一部分 ⭐

**(a) 不是所有问题都该丢给向量检索。**
RAG 不等于"什么都 embedding 一下"。目录、精确条文号、元信息（现行/作废）这类**结构化查询**，
用确定性工具查又快又准，且**不会编造**（工具查不到就返回 found=false + 相近条文号提示，而非让模型现编）。
**先分清"语义问题"和"查表问题"，再决定用检索还是用工具。**

**(b) 集成顺序本身就是 agent 架构设计。**
同样的 agent、同样的工具，**放在场景识别前还是后，结果完全不同**——放后面，
"你收录了哪些规范"会被判成模糊提问兜底掉，工具永远跑不了。
但也不能无脑放最前：敏感/作废这类**红线兜底必须优先于任何 agent**。
所以正确解法是**分层**：硬短路 → agent → 软兜底。

**对 AIPM 转行的启示**：
- **面试金句**："我给 agent 加工具时踩了两个坑——二次调用漏传 tools 导致 tool_call 泄漏成正文；
  以及工具查询被前置的场景识别拦截。后者让我意识到**集成顺序是架构决策**：红线兜底必须在 agent 前，
  但模糊判定要在 agent 后，否则 agent 能力被上游吃掉。"
- **工具设计要"诚实失败"**：`lookup_clause` 查不到返回 hint 而不是空/瞎猜，
  这样 agent 只能如实说"没找到"——**工具层就守住了不编造红线**。

## 五、成本与默认关

tool-agent 对每个 query 加一次 function-calling 判断（+命中时还有工具执行和二次生成）。默认关，因为：
- 多数查询是内容类（用不上工具），全量加一次判断不划算。
- **未来**：用廉价前置规则（正则匹配"收录了哪些/第X条/还有效吗"）预筛，只对疑似查表类才唤起 agent。
