## 二、改动 1 · fix_units 正则修单位 ²（核心）

**文件**：`backend/scripts/fix_chunks_ocr.py`

### 扫描：3 种 ² 退化形态

全语料扫「人均/每床/每生面积单位」，发现 ² 被 OCR 退化成 3 种：
| 形态 | 例 | 是否本轮修 |
|---|---|---|
| ² 完全丢失 | `0.35m/人` | ✅ |
| ² 误识为 r | `0.50mr/人` | ✅ |
| ² 退化为普通 2（cosmetic）| `m2/人` | ❌ 不碰（Judge/LLM 都认得，W6 D1 启示 54 警示盲修风险）|

### 两个正则（只匹配 /人\|人次\|床\|生 人均面积语境）

```python
# 模式 1（数值）：数字 + m[(r)] + /人床生人次
UNIT_FIX_PATTERN = re.compile(r"(\d(?:[\d.]*\d)?\s*)m(?:r)?(\s*/\s*(?:人次|人|床|生))")
# 模式 2（表头）：括号内单位标签 '(m/人)'、'《mr/人)' → '(m²/人)'
UNIT_HEADER_PATTERN = re.compile(r"([（(《\[【])m(?:r)?(\s*/\s*(?:人次|人|床|生))")
```

**安全边界（为什么不会误伤）**：
- `m²/人`/`m2/人`：m 后紧跟 ²/2，模式要求 m 后直接是 `/` 或 `r/`，匹配失败 → 不碰
- `m³/人`（体积，用水/用气量）：³ 阻断匹配 → 绝不会被改成面积 m²
- `km/人`/`cm/人`/`m/s`/`m/h`：分母不是 人床生人次 → 不碰
- 线性"米/人"在规划规范里不成立，命中的必是面积指标（人工核验 28/28 条全是面积）

### 关键洞察：表头一致化让 blast radius 从 13 → 56

原计划只修 13 处数值。但发现表格列头 `(m/人)`、`《mr/人)` 没修会造成**"表头写 m/人、数值写 m²/人"不一致**（违反 RED LINE 2 精确性精神）。补模式 2 后扩到 **56 处单位修复 / 28 条 chunk**，尤其**核心标准 GB 50180-2018 的人均居住区用地表（表4.0.1/4.0.2/4.0.3）全部 `(m/人)`→`(m²/人)`**。

逐条 dry-run before→after 核验 28 条，无一例外是面积指标（人均用地/绿地/避难/床位/教室面积）。

## 八、🎓 启示 66 · 客观数据修复的"评测可见收益"会被噪声系统性掩盖 ⭐

**现象**：58 处客观正确的 chunks 修复 → 综合 **-0.3** / veto **+1**（表面回归），但实质是改善。

**三层噪声掩盖了真实收益**：
1. **采样有限**：13 条 veto 里只有 Q102 直接命中修复；其余 57 处修复落在**不在评测 veto 集**的 chunks 上 → 真实正确性收益评测看不见
2. **检索扰动（启示 54）**：改 chunk 文本→改 embedding→dim1 召回 -1.7pp = 综合 -0.3 全部来源
3. **Judge 方差（启示 53）**：veto churn 11/19，多数 QID 未被任何修复触及却进出 veto 集

**等价表述**：
> 当"体感工作量大"（58 处修复）但"综合分平/微跌"时，要区分
> **"没效果" vs "效果被噪声掩盖"**——后者靠：① 看正确性子维度（dim4/dim7）而非综合分；
> ② 多次评测取交集（启示 53）；③ 归因每条新 veto（排除修复致错）。

**对 AIPM 转行的启示**：
- 数据治理的价值**不能只用单次评测综合分衡量**；客观正确性是独立于评测的产品资产
- 这是启示 64（chunks 是评测可信度天花板）的延伸：修天花板的收益**部分不可见**，但仍要修——因为评测集会扩、用户 query 会变，今天看不见的正确性明天就是命中
- 与启示 65（知道何时停止）的张力：停止"追评测分"≠ 停止"修客观错误"。前者边际收益递减，后者是正确性底线
