## 一、一句话定位

做一个"像查法条"的 RAG 规范问答助手，从 W1 到 V2，**真正沉淀下来的不是代码，是"如何在黑盒 LLM + 脏数据 + 噪声评测下，做出可信产品"的判断力**。77 条洞察可归为 8 大主题。

## 二、8 大主题

### 主题 A · 评测方法论 —「评测集是镜子，但镜子本身要先校准」
- **33** 数字会骗人，评测集是照出真实水平的镜子
- **34/35** 评测集是"循环可信化"的、是测 RAG 也测 pipeline 盲点的**双向探针**
- **38/45** 多指标多维度才看清模型行为；**综合分与 veto 是两个独立验收维度**
- **39/42** "假阳性"比"失败"更隐蔽；扩量本身会再次揭穿假阳性
- **53** 单次 LLM Judge 有 ~50% 噪声，**三次交集**才是真 veto
- **66/67** 客观修复的收益会被噪声系统性掩盖；**二值阈值指标比连续指标对噪声敏感得多**
- **70** chunk-grounded 自动生成的评测偏乐观，测了覆盖、没测难度

### 主题 B · 检索 / RAG 工程
- **16/17/18** 召回与精度是两条独立赛道；**正确归因比"总体涨多少"更重要**；别为难"病在别处"的指标
- **40** 不存在"通用最佳"配置——**业务 KPI 决定参数**
- **47** citations vs search 的差距 = RAG 的"用对率"
- **69** 语料 2x，检索质量近乎无损，但**评测覆盖滞后是盲区**
- **72** 多轮对话用"检索侧 query 重写"，**不把历史塞进生成**（守 grounded）

### 主题 C · LLM 编造治理 + 红线守护（本项目的命门）
- **29/30/31** "礼貌拒答"是核心能力；优先级链是兜底设计核心；分段判定 > 单一阈值
- **46** LLM 编造有 4 种典型模式，**可工程治理**
- **52/55** "补充说明"是 LLM 难根除的训练惯性 →`post_filter` 是其工程化解药
- **54** 数据质量↑ ≠ 产品质量↑（**chunks 干净反让 LLM 更敢编造**）
- **56/58** 顽疾主矛盾会随治理切换；用词错与编造同源、prompt 治不了
- **59/60/62** 后处理可链式叠加，但**不是无条件**叠加
- **65** 三管齐下后，剩余顽疾的"质"变了

### 主题 D · 数据质量 / OCR —「上游脏，下游全脏」
- **49/64** PDF OCR 是隐藏的评测干扰项；**chunks 质量是评测可信度的天花板**
- **50** 评测工具自身的故障是评测结论的隐藏变量
- **71** OCR 错分两类（系统性 vs 随机弥散），字典扩充靠**"占用次数 + 上下文验证"三步法**
- **74** 数据损伤是**多模态的**（替换/乱码/汉字错乱），单一探针必漏报；扩量/补覆盖前**先体检数据**

### 主题 E · 失败处置 & 诊断纪律
- **14/23** 诊断要诚实、不做"假设驱动开发"；失败要诚实记录、不藏
- **15/21** "改了不涨"也是成果；**"改了反而劣化"是更宝贵的成果**
- **24/28** "保留代码 + 默认关 env flag + 文档解释"= 失败实验的标准处置
- **25** "诊断假设 ≠ 改造假设"（最深的失败模式）
- **26/27/63** 黑盒模型有参数调优天花板；连续失败要有纪律；**LLM 不会真心 self-doubt**

### 主题 F · 调试纪律
- **61** 端到端集成测试缺位，让一个 SSE bug 活了 5 周
- **68** 相同症状 ≠ 相同根因，用**分层隔离**快速定位真/假 bug
- **73** 区分"陈旧日志缓冲"与"真实错误"：**看增量不看存量、主动埋点复现**

### 主题 G · 产品 / 前端工程 & 高 ROI 判断
- **57** 流式 + 后处理的"双事件"集成模式
- **75** 占位 UI 常把"暂时省略"硬编码成**虚假的非此即彼**，加真数据前先拆正交维度
- **76** 最高 ROI 的功能常是"**接通早已铺好却没接 UI 的潜在能力**"
- **77** **优先用平台原生原语，能不引库就不引**

### 主题 H · AIPM 软技能 / 协作
- **19/32** 工程债要立刻记账；TODO 是技术债的可见性工具
- **20** LLM 改写效果跟 prompt 示例质量强相关
- **36/41** "温柔挑战"是 AI 协作关键；**AI 草稿 + 业务专家审 = 不可分割**
- **43/44** 用户反馈是"累计训练曲线"；规范层级 / 业务视角分工是评测集质量的隐藏维度

> 早期 W1-W2 的 13 条（1-13）是基础铺垫（RAG 概念、分块、向量、首版评测），已被上述主题吸收。

## 三、转行面试可直接讲的 10 条"金句"

1. **数据质量↑ ≠ 产品质量↑**——chunks 修干净后 LLM 反而更敢编造（启示 54）。讲"反直觉发现 + 工程化解药 post_filter"。
2. **单次 LLM Judge 有一半是噪声**，三次交集才算数（启示 53）。讲"不信单次评测、用方差分析定信度"。
3. **"改了反而变差"是更宝贵的成果**（启示 21）——讲失败实验的科学处置（保留代码+flag+文档）。
4. **绿色仪表盘可能只是没测到**（启示 73/74）——讲"单一指标必漏、多探针交叉、看增量不看存量"。
5. **最高 ROI 功能 = 接通早已铺好却没接 UI 的潜在能力**（启示 76）——讲"先盘存量再造新的"。
6. **多轮对话用检索侧 query 重写、不把历史塞进生成**（启示 72）——讲守住"答案只来自当前证据"的红线。
7. **OCR 损伤是多模态的，补覆盖前先体检数据**（启示 74）——讲"负面结论也是交付"。
8. **占位 UI 常硬编码进虚假假设**（启示 75）——讲"接真数据前先拆正交维度"。
9. **自动化给候选、人卡红线**（启示 71）——8 个 OCR 候选过验证只活 2 个，淘汰 75%。
10. **优先平台原生原语、能不引库就不引**（启示 77）——讲依赖的隐性税。
