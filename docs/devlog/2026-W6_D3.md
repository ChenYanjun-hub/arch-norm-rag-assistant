## 四、🎯 启示 58 候选 · dim4 用词错也是 LLM 训练惯性（prompt 治不了）

### 失败的 4 个机制解读

#### 1. DeepSeek 对长 in-context 反例不够敏感

5 个反例 + 自检流程让 prompt +80% 长度，但 dim4 +0pp。可能是 DeepSeek-chat 训练时
对 ICL（in-context learning）的反例对齐能力较弱。

#### 2. dim4 错误的根因不是"LLM 不知道用词差异"

prompt 已经说得很清楚："宜"是推荐性、"不应"是强制性。LLM 看到这段话后还是会换。

→ 根因是 LLM 的"标准化训练惯性"：把不同量词压扁成"应"，因为日常语料中"应"频次最高。

#### 3. 长 prompt 的副作用让 dim3/dim5 下降

加 800 字 few-shot 后：
- dim3 引用准确 99.1% → 96.6%（-2.6pp）
- dim5 数字精确 93.1% → 91.4%（-1.7pp）

机制：LLM 注意力分散到 prompt 末尾的反例上，对主答案的引用 / 数字精确度反而降低。

#### 4. 等价于启示 52（"补充说明"训练惯性）

dim4 用词错与 dim7 编造（补充说明）是**同一类问题**：
- LLM 训练惯性
- prompt 写得再严无效
- 必须后处理代码层治理

### 启示 58 完整表述

> dim4 用词错与 dim7 "补充说明" 是同一类 LLM 训练惯性问题。
> 5 条 few-shot 反例对 DeepSeek-chat 完全无效，反而让 dim3/dim5 因 prompt 长度副作用下降。
> 治 dim4 必须靠后处理：`_align_modal_verbs()` 函数自动 diff chunks 与 LLM 输出的量词。

### 应用

**W6 D4+ 路线（暂缓决策，等用户审核）**：

写一个 `_align_modal_verbs()` 后处理函数：
1. 从 chunks 文本中提取所有量词（应/宜/不应/不宜/可/不可/严禁/必须）的上下文
2. 扫描 LLM 答案中相同位置的对应量词
3. 如果不一致 → 自动改回 chunks 原词
4. emit `revised_answer`（复用 W6 D2 的事件模式）

预期：dim4 85.3% → 95%+（直接锁定原词，几乎无法错）。
