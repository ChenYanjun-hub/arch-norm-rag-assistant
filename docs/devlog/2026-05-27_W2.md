## 三、踩的坑

### 坑 1：smoke_rag.py 启动报 `ModuleNotFoundError: No module named 'openai'`

- **原因**：requirements.txt 写了 openai 但 venv 中没装（之前只装了 chunker + ML 包）
- **修复**：`pip install openai tenacity`
- **教训**：requirements.txt 不是真相，`pip list` 才是。多模块项目要分阶段验证依赖

### 坑 2：FastAPI 启动报 `no such file or directory: .venv/bin/uvicorn`

- 同上：fastapi / uvicorn / sse-starlette / python-multipart 全部没装
- 一次性补：`pip install fastapi uvicorn[standard] sse-starlette python-multipart`

### 坑 3：LLM 拒绝回答"幼儿园服务半径"

- **现象**：query "居住区配套幼儿园的服务半径不应大于多少米？" → LLM 返回"未在现行规范库中查询到该问题的依据"
- **诊断**：检索 hit @ 表 5.0.3，但表 5.0.3 实际是「配套设施用地控制指标表」，不含"服务半径=300m"。真正的"300m"在附录 B 的另一个表里
- **结论**：**这是红线 1 完美生效**——LLM 严格遵守"chunks 没有就不答"。说明 SYSTEM_PROMPT 在实战中确实可信
- **后续行动**：W3 阶段加入 reranker + 改进 chunker 对表格的切分粒度（表格内单元格内容也要可检索）

### 坑 4：Python 3.9 默认参数语法问题（昨晚遗留）

- 已在 W1 Day 1 时通过 brew install python@3.11 解决

## 六、关键观察 & AIPM 视角洞察

### 观察 1：SYSTEM_PROMPT 在生产环境的"自证"

query "居住区配套幼儿园的服务半径" 这条，LLM 看到 5 个 chunks 里没有具体数值，**主动拒绝编造**：

> 未在现行规范库中查询到该问题的依据。
> 依据说明：您提供的规范片段中，[1] 涉及居住区道路与建筑物的最小距离，[2][3][4][5] 涉及配套设施配置原则、分级控制规模、设置规定及控制指标，均未包含"幼儿园服务半径"的具体数值规定。

这是 PRD 红线 1 的完美实例——**Prompt 工程从纸面规则变成了运行时行为**。

### 观察 2：检索 hit ≠ 答得对

我们的 Hit Rate@5 = 100%，但这条 query 实际"答不出来"。原因是表 5.0.3 chunk 内容里没有"幼儿园服务半径"的具体数值（在另一个表里）。

**对 AIPM 的启示**：评测要分两层
- **检索层**：相关 chunk 是否进入 top-k（当前关注点）
- **生成层**：基于召回的 chunks 能否产出正确答案（更难的关注点）

V2 评测体系需要补"答案正确率"独立指标，不能只看 Hit Rate。

### 观察 3：场景识别的成本意识

闲聊和超范围 query 走完整 RAG 流的话：
- BGE-M3 编码：~100ms
- Qdrant 检索：~50ms
- DeepSeek 调用：~2000ms（含 TTFT）
- 总成本：~2150ms + 1 次 LLM 调用费用

加上 60 行正则识别，可以**0 ms 拦截，0 LLM 费用**。

42 条规范、4773 chunks 的系统，可以预见**至少 30% 的用户 query 是边角情况**。提前拦截相当于显著降低运营成本。

### 观察 4：API 设计的"早开放"价值

今天 30 分钟写完 /api/chat SSE 端点，前端立刻可以接。如果留到 W3 再做，会发现：
- 前端开发会卡在等后端接口
- 后端为了赶接口可能漏入参校验
- 双方对 SSE 事件结构有口头约定但没文档

**对 AIPM 的启示**：API 是前后端的"契约表面"，应该在主流程跑通后**立刻冻结对外接口**（事件类型 + 字段 schema），即使内部实现还会变。
