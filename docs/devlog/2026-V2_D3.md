## 三、全语料 OCR 体检（89 部）

详见 [`docs/eval/ocr_full_corpus_audit_2026-06.md`](../eval/ocr_full_corpus_audit_2026-06.md)。三个核心发现：

1. **损伤语料级，非新增独有**（推翻假设）：乱码探针 原始41部 1.2/k ≥ 新增48部 0.8/k；GB50033（采光·原始）公式都被毁成「C= ×1008」。
2. **损伤 ≥3 模态，单指标必漏**：(a)同形替换→LLM校对 / (b)拉丁数字乱码→嵌拉丁探针 / (c)**汉字错乱→两者全漏**。铁证：CJJ 45-2015 自动指标三项全绿，实为 mode-(c) 重灾区（假干净）。
3. **廉价指标双向不准**（漏 mode-c + 公式误报）→ 自动排不出可靠 re-OCR 清单，需 LLM 语义连贯打分或人工抽样。

**字典快速收益**：8 个系统候选过 context-verify **仅 2 条幸存**（指施→措施、规刘→规划），6 条全毙（3 危险单字 / 区城市7处合法边界 / 多混地震 / 城面只在烂块）。已应用 + reindex（98 处/94 chunk/40 文件）。规划是产品核心词，"规刘"必修。

## 四、🎓 启示 74 · 数据质量是多模态的，单一探针必漏报；"补覆盖"前先体检数据 ⭐

**对 AIPM 转行的启示**：
- **OCR/数据损伤不是单一现象**：同形替换、字符乱码、语义错乱是不同失效模式，各需不同探针，没有一个廉价指标能全覆盖。CJJ45「三项全绿却是重灾区」是最贵的一课——**绿色仪表盘可能只是没测到**（与启示 73「看增量、主动复现」同源：别信单一指标的表面读数）。
- **"补覆盖/扩量"前先验数据质量**：本想补 4 部评测覆盖，结果发现源数据烂到做不成标准答案。**先体检上游数据，再决定下游动作**——否则会拿垃圾当真值（差点违 RED LINE 2）。
- **候选淘汰率是纪律的体现**：8 个 LLM 给的"系统性错字"候选，过边界验证只活 2 个（淘汰 75%）。自动化给候选、人来卡红线——这个分工不能省（再证启示 71）。
- **负面结论也是交付**：体检没产出"干净 re-OCR 清单"，但产出了"为什么排不出 + 该用什么方法 + 当前定位"——对决策同样有价值，别因为"没拿到预期产物"就藏起来。
