## 四、5 个核心发现（详见报告）

### 1. multi-query 在 v3.1 上 0 改善 → W3 D2 +2.6pp 是假阳性

**A vs B 数字完全相同**：
- A (mq=on): strict 32.3% / loose 80.6%
- B (mq=off): strict 32.3% / loose 80.6%
- 时延 17.7s → 3.9s (-78%)

W3 D2 报告的 "+2.6pp loose" 在 v3.1 上完全无法复现。
**根因**：v2 集 16 条废条（spec 错位），multi-query 的 3 变体"广撒网"恰好命中其中几条的"相似 spec"，造成假阳性。v3 修对后没了。

### 2. reranker 双面性

| pair | Δ strict | Δ loose |
|---|---|---|
| A vs C（rk on→off, hyb on）| +3.2pp（rk 害 strict）| -6.4pp（rk 救 loose）|
| E vs F（rk on→off, hyb off）| 0pp | -12.9pp（rk 救 loose）|

**reranker 救 loose 始终（+6 到 +13pp），但 hyb=on 时害 strict（-3.2pp）。**

这解释了 W3 D4 调参全 0 改善的真正原因：不是参数问题，是 **reranker 本身在 strict / loose 上反向**——调参不能改这个矛盾。

### 3. hybrid 在 v3.1 上仍负 loose（W3 D3 结论部分成立）

A vs E（hyb on→off, rk=on）：strict +3.2pp / **loose -3.3pp**

W3 D3 报告的 "-2.6pp loose" 在 v3.1 上 **复现为 -3.3pp**（成立）。
但 W3 D3 没观察到：**hybrid 同时帮 strict +3.2pp** → 是双面刃，不是简单负优化。

### 4. 域差异显著

**规划域反直觉**：
- C（关 reranker）+ E（关 hybrid）规划域 81.8%（+9.1pp）
- F（全关）规划域降到 63.6%（-9.1pp）
- 说明规划域只需 **reranker XOR hybrid 一个**——两者都开或都关都不是最优

### 5. 最佳配置取决于业务目标

| 目标 | 最佳组合 | 数字 | 时延 |
|---|---|---|---|
| 最高 loose（找对规范） | **E** | **83.9%** | 4.3s |
| 最高 strict（找对条款） | **C** | **35.5%** | 1.9s |
| 最便宜（时延） | F | 71.0% / 32.3% | **0.4s** |

**产品定位 "AI 法条数据库"，loose 是 KPI** → **E 配置（mq=on + rk=on + hyb=off）**。

但 A vs B 证明 multi-query 在 E 上也应该 0 改善 → 实际生产可关 mq 进一步省时延。

## 五、立即落地的工程决策

### 修改 `config.py` 默认值

`MULTI_QUERY_ENABLED`：`true` → **`false`**

**理由**：
- v3.1 6 组合矩阵证明 mq=on/off 数字完全相同
- mq=on 时延翻 4 倍（17.7s vs 3.9s/条）
- 生产 baseline 走 mq=off 等价 + 更便宜

**保留代码 + env flag**（启示 24/28：失败实验标准处置）：
- `app/rag/query_rewriter.py` 完整保留
- `app/rag/retriever.rrf_fuse()` 完整保留
- 用户 `MULTI_QUERY_ENABLED=true` 一键启用

## 七、4 个新 AIPM 启示（37-40）

### 启示 37 · 评测集变化触发全链路重审
评测集从 v2 → v3.1，不只看总体数字，还要 **逐个复测上层实验结论**。否则有"基于假阳性的算法决策"作为隐藏技术债。

### 启示 38 · 多指标 + 多维度才能看清模型行为
W3 D3 看 loose 一个数字判定 "hybrid 是负优化"。
今天看 strict + loose 双轴，发现 hybrid 是 **双面刃**（+strict / -loose）。
评测不是一张表——要看 strict / loose / MRR / by-domain / by-difficulty 全方位拼图。

### 启示 39 · "假阳性"比"失败"更隐蔽
W3 D3 hybrid 失败：当天 -2.6pp 就发现，立刻关默认 + 文档。
W3 D2 multi-query "+2.6pp"：作为 SUCCESS 沉淀进 commit、devlog、AIPM v4.0 启示 17，**潜伏 4 天才被 W4 D4 揭穿**。

**AIPM 防御性思维**：每个"成功"实验都要做 **延迟回归测试**——评测集更新后重跑，确认结论仍成立。

### 启示 40 · 不存在"通用最佳"——业务 KPI 决定配置
- 想要 loose 最高 → E 配置
- 想要 strict 最高 → C 配置
- 想要时延最低 → F 配置

AIPM 核心工作是 **对齐业务 KPI 与技术配置**。
"AI 法条数据库" loose 关键 → E 配置（默认建议）。
