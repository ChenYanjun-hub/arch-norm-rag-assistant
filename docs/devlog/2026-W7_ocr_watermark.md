## 一、先复核清单：原 P0 是误报

清单把 `CJJ/T 91-2017` 的 4.1.1 / 4.2.4 列为「P0 · 直接毁答案」，说正文毁成 `"public parl R"` / 为空。
动工第一步是复核，结论相反：

| clause | type | 页 | 长度 | 中文占比 | 实况 |
|---|---|---|---|---|---|
| 4.1.1 | **clause** | 12 | 75 | 0.67 | **定义完整** |
| 4.1.1 | appendix | 49 | 19 | 0.00 | `public parl R` ← 清单看的是这个 |
| 4.2.4 | **clause** | 14 | 63 | 0.52 | **定义完整** |
| 4.2.4 | appendix | 46 | 5 | 0.00 | 只有条号 |

乱码的是 `type=appendix`——标准末尾的**中英文索引页**。索引页本来就只有「术语 + 页码」，
短、中文占比低是**正确的数据**。原扫描口径（长度 <12 字 或 中文占比 <0.12）把索引和正文混着看了。

**决定性验证**是端到端问一遍：

- 「什么是公园绿地？」→ 引 `4.1.1`，完整给出「向公众开放，以游憩为主要功能…」✅
- 「绿地率和绿化覆盖率区别？」→ 引 `4.2.4/4.2.3`，正确区分「各类绿化用地面积」vs「植物垂直投影面积」✅

**省下的功**：这两条本来要「重新 OCR PDF 页 + 重新分块入库」。

## 二、真缺陷是清单里没有的那个

顺手扫全语料，撞到覆盖面大得多的一类：

| 指标 | 数值 |
|---|---|
| 受污染 chunk | **1212 / 10785（11.2%）**，42 部规范 |
| 噪声行（水印 + 紧贴页码） | 4173 行 |
| 水印落正文中间、切断句子 | 897 条 |
| **水印落在用户可见 `original_text[:200]`** | **928 条（占受污染 77%）** |

「住房城乡建设部信息公开 / 浏览专用」是 PDF 页脚水印被 OCR 当正文抓进来。
最刺眼的形态是它出现在**引用卡的原文摘引**里——例如用户查「城镇道路养护设备配备」，
引用卡上会显示：

> `3.0.10 城镇道路养护应按养护面积配备养护设备、检测设备及专业养护技术人员。` **`4 住房城乡建设部信息公开 浏览专用`**

对一个主打「像查法条一样查规范、原文可追溯」的产品，**在引用的条文里混进水印直接伤可信度**。

## 三、修法：精确白名单整行删（红线保护）

全语料含关键词的整行共 **24 种**，23 种是水印被 OCR 截断的残片
（`住房城乡建设部信息公` / `部信息公开` / `住房城乡建谈浏览专用` …），
**但第 24 种是正经条文正文**：

> `馆一般在20 万人口以上的城市设置。2017 年国家发展改革委住房城乡建设部印发《关于规`

**写成 `住房城乡建设部.*` 之类的正则就会删掉真条文（红线 1/2）。**
所以规则定成：**只删「整行 strip 后完全等于」23 种已核形态之一的行**。
配套只在**紧贴被删水印行**时才删纯数字行（页码）——否则会误删条文列项序号「1」「2」。

关键性质：**只做整行删除，不改任何保留行的字符** → 不可能动到规范用词（红线 3）。
删除后相邻行自然接上，被切断的句子随之复原：

```
修复前： …用火、用电和用气均应符合消 / 住房城乡建 / 防安全要求 / 浏览专用
修复后： …用火、用电和用气均应符合消 / 防安全要求
```

11 条单测锁住行为，含一条专门守红线：**正文里提到"住房城乡建设部"的真条文绝不能被删**。

### 生成：LLM 比我以为的鲁棒

我动工的主要理由是「断句会让 LLM 引错原文（红线 3）」。做了 A/B（同 query，temperature=0，
一份喂带水印的 chunk、一份喂清理后的）：

**两版都正确引出「均应符合消防安全要求」——预判的误引风险没有发生。**
唯一差异是清理后覆盖了 5/5 个子项（带水印那版漏了「外脚手架」这一项），n=1 不足以泛化。

### 所以本次修复已证实的收益是

✅ **928 条 chunk 的用户可见原文摘引变干净**（可信度，产品定位的核心）
✅ prompt 噪声字符 **-1.21%**
❌ **不是**可测量的答案准确率提升
❌ **不是**红线 3 风险消除（该风险经验证不存在）

**要不要保留这次修复？保留。** 它修的是一个真实、用户可见、且与产品定位（可追溯原文）
直接冲突的缺陷。但**报告收益时必须按实测口径说，不能按动工时的假设说。**

## 五、顺带查清的两件事

- **P1 的 5 条"空正文"不是 OCR 识错，是阅读顺序 + 分块规则不匹配**：
  PDF 文本层里条号排在句子**后面**（"…应符合表5.3.5的规定 ⏎ 5.3.5"），
  分块器按"条号在行首"切 → 切出空 chunk。**数据没丢**，表格作为独立 `type=table` chunk 存在且有数值。
  根治要改分块器（条号后置容错）＝ CLAUDE.md E.1 硬约束，**需拍板，本轮不擅自改**。
- **曾疑的红线 2 错条号：不存在**。`CJJ 193-2012` 6.6.1 的内容没有被错挂到 6.6.6
  （grep 命中的是 6.6.6 自己的同类句子）。

## 六、🎓 启示 94 · 修复的价值要事后用数据重新认定 ⭐

我带着两个假设动工：①清单上的 P0 是真的 ②断句会导致 LLM 误引原文。
**两个都被数据否掉了**——P0 是误报，LLM 对断句鲁棒。
而真正值得修的缺陷（水印进引用卡）是**扫描时撞上的、清单里没写的**，
它的价值也**不是我原本以为的那个**（不是准确率，是可信度）。

**对 AIPM 转行的启示**：
- **动工前先复核缺陷清单，判定缺陷要端到端跑一遍**。用静态特征（长度、中文占比）判缺陷会误报；
  这次省下了两次"重新 OCR + 重新入库"。
- **饱和区指标不能用来做决策**。rerank 分数挤在 0.99+ 时，top-1 / MRR 的抖动是测量噪声，
  不是质量信号。看清"分差 0.001、换的是同规范相邻条文"才敢说无回退。
- **假设被否掉时，重新认定价值，而不是改口径把数据说圆**。
  正确写法是"已证实收益 = 用户可见原文干净 + 噪声 -1.21%；预判的红线风险经验证不存在"，
  而不是"修复后答案质量提升"。
- **区分"该修"和"修了会涨指标"**。这次是该修但不涨指标——
  产品定位是「可追溯原文」，引用里混水印本身就是缺陷，不需要靠 KPI 提升来给它找理由。
