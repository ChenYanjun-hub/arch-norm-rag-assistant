**日期**：2026-06-16（V2 D6）
**分支**：main

## 一、背景

右栏「规范出处」三 tab：条文（已做）、PDF 原文（disabled 占位）、关联（disabled 占位）。后端 `/api/spec/{code}` 早能 inline 返回 PDF（单卡"查看原文 PDF"靠它新标签打开），但 tab 内嵌没做。本轮做 PDF 内嵌、砍关联（关联需先定义"关联"语义，未想清，砍）。

## 二、实现（2 文件，零新库）

- `RightPanel.tsx`：
  - 加 `tab` 状态；条文/PDF 两 tab 真切换；**删关联 tab**
  - PDF tab：`<iframe src="/api/spec/{code}#page=N">` —— 浏览器自带 PDF 阅读器渲染、`#page` 锚点定位被引页；`key={code:page}` 强制重挂，确保切换时锚点重新生效
  - 多引用 → 顶部 `[1][2]…[N]` 切换 chip（点击复用既有 `activeIndex`）+ 元信息行（《规范名》· 标准号 · 第 N 页）+ "在新标签页打开 ↗" 兜底
  - 引用为空（兜底场景）→ 自动回退「条文」tab，PDF tab 禁用
- `design.css`：`.cn-pdf-switch/.cn-pdf-chip/.cn-pdf-meta/.cn-pdf-open`

## 四、🎓 启示 77 · 优先用平台原生原语，能不引库就不引 ⭐

内嵌 PDF 有两条路：引 `pdf.js`（功能强但是新依赖，要走 CLAUDE.md B.1 审批 + 体积 + 维护），或 `<iframe>` + 浏览器自带 PDF 阅读器 + `#page` 锚点（零依赖）。选了后者：2 文件、没引一个库就把功能跑通。

**对 AIPM 转行的启示**：
- **先问"平台/浏览器原生能不能做"，再考虑引库**：iframe、`#page` 锚点、`<details>`、原生 PDF/视频/日期控件……很多需求平台早给了原语，引库往往是没盘清原生能力的惯性。
- **每个依赖都有隐性成本**：审批、体积、安全面、长期维护、版本升级。原生方案少这些税，还更稳。
- **够用即可**：内嵌阅读器要的是"原地看到被引页"，原生 iframe 完全满足；pdf.js 的高级能力（批注/搜索/自渲染）这里用不上——别为用不上的能力背依赖。
- 与启示 76 互补：76 是"接通已有能力"，77 是"用平台已给的原语"——都指向**先盘存量再造新的**。
