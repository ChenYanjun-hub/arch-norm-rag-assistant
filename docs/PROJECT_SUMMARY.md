# 建景规规范问答助手 · 项目结题总结

**项目名**：建景规规范知识问答助手（Architectural Norm RAG Assistant）
**项目阶段**：W1-W7 MVP + 治理迭代 + 评测方差控制 7 周
**当前口径**：**综合 89.9±0.5 / 3 次交集真顽疾 6（0 条 LLM 真错）**（W7 D5 方差受控，116 条 ×3 次）
**里程碑**：v1.0-mvp（86.6）→ v1.1（88.3）→ **v1.2 tag（W7 D3 单次 90.3）** → W7 D4 chunks v3（Keep）→ W7 D5 方差受控
**最后更新**：2026-06-14

---

## 一、项目定位

> **"AI 版规划/建筑/景观/消防/结构规范的法条数据库"**

面向中型设计院规划师的 RAG 智能查询工具，回答**严谨权威 + 可追溯到原文**，不做聊天伙伴。

### 1.1 解决什么问题

规划/建筑/景观/消防/结构 5 类规范散落在 39+ PDF 中（共 ~6000 条条文），设计师查阅困难：
- 关键词搜索难定位精确条款
- 跨规范查询需开多个 PDF 对照
- 强制性条文用语易混淆（应/不应 vs 宜/不宜）
- 数字数据（服务半径/绿地率/容积率等）查询慢

### 1.2 产品红线（CLAUDE.md 4 条）

- 🔴 不允许编造规范信息
- 🔴 引用必须精确（规范全称 + 标准号 + 条文号 + 跳转）
- 🔴 强制性条文用语不可错（应/不应/宜/不宜 不可混用）
- 🔴 不写 chunks 之外的"建议"

## 二、技术架构

### 2.1 技术栈（CLAUDE.md B.1 锁定，全程未变）

```
后端：Python 3.11 + FastAPI + LangChain + qdrant-client + sentence-transformers + openai SDK
前端：Node.js 18 + React 18 + TypeScript + Vite + Tailwind CSS + zustand
基础设施：Qdrant 1.x (local file mode) + SQLite + Nginx
第三方：DeepSeek API (主, deepseek-chat) + 通义千问 Max (备)
```

### 2.2 RAG Pipeline 流程

```
用户 query
  ↓
[1] 输入校验 + 场景识别（8 类边界兜底）
  ↓
[2] Query 改写（W3 D2 加 · 多 query 召回）
  ↓
[3] 向量检索 (BGE-M3 1024-dim + Qdrant cosine)
  ↓
[4] Rerank (BGE-Reranker-v2-m3, top-20 → top-5)
  ↓
[5] DeepSeek 流式生成 (SYSTEM_PROMPT_MAIN 7 条规则 + 4 条防编造硬约束)
  ↓
[6] 流末输出 citations + metadata(dangling_count)
  ↓
SSE 流式返回到前端
```

### 2.3 最终上线配置（Combo E）

经 W4-W5 6 组合 regression 验证：

| 配置 | 设置 | 选择理由 |
|---|---|---|
| multi_query | ✅ ON | regression loose 93.1% 最优 |
| reranker | ✅ ON | 关键质量保障 |
| hybrid (BM25) | ❌ OFF | hyb=on 害 loose -1pp |

## 五、W5 最终量化结果

### 5.1 RAG 系统综合质量（W7 D5 方差受控口径 · 116 条 ×3 次）

| 验收项 | 验收线 | **实测（方差受控）** | 通过 |
|---|---|---|---|
| 综合得分 | ≥ 75（GREEN）| **89.9 ± 0.5 / 100**（89.4~90.5）| ✅ +14.9 |
| 一票否决项（**单次** Judge）| = 0 | 14.3 ± 2.9（11~18）= 不可作决策依据 | ⚠️ 噪声 |
| **真实 veto 顽疾**（**3 次交集**，纯噪声受控）| = 0 | **6 / 116（5.2%）· 0 条 LLM 真错** | ❌ 但全为 chunks 错/算法局限 |
| RAG 配置 | 通过 regression 验证 | Combo E loose 93.1% | ✅ |

> ⚠️ **口径说明**：单次 veto（11~18）78% 是 Judge 噪声，**已弃用**；真顽疾以 3 次交集为准 = **6 条**
> （Q003/Q112/Q128 chunks 错 + Q079/Q109/Q139 align 局限，**0 条 LLM 真编造/真用词错**）。
> dim1 召回 3 次方差 = 0（无 Judge 对照）→ 证明波动全来自 Judge，非 RAG。详见 [W7_D5_variance_report.md](eval/W7_D5_variance_report.md) / [eval_scope_decision.md](eval/eval_scope_decision.md)。

### 5.2 7 维度进化（v1.0-mvp → 方差受控）

| 维度 | v1.0-mvp | v1.1 | v1.2 单次 | **方差受控(3次均值±std)** |
|---|---|---|---|---|
| dim1 检索召回 | 84.5% | 83.6% | 84.5% | 82.8% ± 0.0 |
| dim2 精确条款 | 67.2% | 68.1% | 68.1% | 68.1% |
| dim3 引用准确 | 98.3% | 99.1% | 100.0% | 99.1% ± 0.0 |
| dim4 原文用词 | 86.2% | 88.8% | 94.0% | **94.5% ± 2.5** |
| dim5 数字精确 | 94.0% | 94.0% | 93.1% | 94.0% ± 1.2 |
| **dim7 不编造** | 76.7% | 87.9% | 97.4% | **97.7% ± 0.4** ⭐⭐ |
| **综合** | **86.6** | **88.3** | **90.3** | **89.9 ± 0.5** ⭐ |
| **veto 单次** | 38 | 27 | 13 | 14.3 ± 2.9（噪声，弃用）|

> dim7 不编造 76.7% → 97.7% 是项目最大跃升（post_filter + align + chunks 三管齐下）。
> v1.2 单次 90.3 落在方差带 89.4~90.5 的高端——方差受控均值 89.9 是更诚实的口径。

### 5.3 关键洞察：单次 Judge 噪声 ~78%（W7 D5 实证升级）

| 时点 | 方法 | 真顽疾 | 噪声证据 |
|---|---|---|---|
| W5 D5 | 单次 vs 3 次交集 | 14（vs 单次 35-38）| ~50% 噪声（启示 53）|
| **W7 D5** | 同-chunks ×3 次纯噪声 | **6（vs 单次 11-18）** | **78% 噪声 + dim1 方差=0 对照** |

**W7 D5 升级结论**：同一份 chunks 重跑 3 次，veto 单次 11/18/14（±2.9），但 3 次交集只有 6 条 → **并集 27 中 21 条（78%）是 Judge 噪声**。dim1（无 Judge 对照）方差 = 0，证明波动 100% 来自 Judge 而非检索。

**二值阈值放大噪声（启示 67）**：综合（连续均值）±0.5 稳，veto（二值阈值）±2.9 炸 → headline 用连续分+方差带，找真问题用多次交集。

**6 条真顽疾归因**：Q003/Q112/Q128 chunks 错（启示 64）+ Q079/Q109/Q139 align 局限（启示 62），**0 条 LLM 真错**（启示 65）。

## 六、项目未达成（GREEN 卡点）

### 6.1 dim7 编造（78.2% / 35 条触发）

**4 种典型编造模式（W5 D3 归纳）**：
1. 编造引用号 [4][5][6] — **修复 ~75%** ✅
2. 补充说明区编造 — **修复 ~0%** ❌（顽疾）
3. 编造"强制性条文"标签 — 修复 ~33%
4. 编造跨规范引用 — 修复 ~0%

### 6.2 W6+ 改进方向（已沉淀到 AIPM 启示 52）

- **后处理 strip 整段"补充说明"/"另注"/"备注"节** — prompt 写得再严也根治不了 LLM 训练惯性
- chunks OCR 质量提升 — PDF 错字会污染 Judge 判断（启示 49）
- LLM Judge 自身防 hallucinate 加固 — Judge 准确率 60-70% 仍可提升

## 八、上线决策（项目结题判定）

### 8.1 推荐结论

**YELLOW（限定场景上线）**：
- 综合 **89.9 ± 0.5** ✅ 远超 75 GREEN 线
- 真顽疾 6（3 次交集）⚠️ 但 **0 条 LLM 真错**（全为 chunks OCR 残留 + align 算法局限）
- 适合**专业设计师**作为查询辅助（能识别残留的数据/算法边界问题）
- 不适合**学生 / 非专业用户**单独依赖最终合规结论

### 8.2 不推荐 GREEN 上线的原因

- veto = 0 的硬门槛未达成（但单次 veto 78% 是 Judge 噪声，真值为 3 次交集 6 条）
- 6 条真顽疾需数据治理（chunks OCR 残留）/ 算法精修（align）突破，非 prompt 可解
- LLM 输出层已达工程上限（启示 65），剩余靠数据层

### 8.3 不应回退 RED

- 综合 89.9 远超 60 红线
- dim7 不编造 97.7%，[N] 编造 + 跨规范联想 + 补充说明区已三管齐下根治
- 消防域 0% veto 证明 RAG 系统**真正能做到不编造**
