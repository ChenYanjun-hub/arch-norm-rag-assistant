## 🚀 第一次启动 Claude Code（必读）

第一次在项目里启动 Claude Code 时，先把这段话发给它：

```
你好，开始这个项目前，请先做三件事：

1. 阅读项目根目录的 CLAUDE.md，理解所有开发规范和约束
2. 阅读 docs/PRD.docx（如能访问），理解产品需求
3. 列出你的初步理解：
   - 这个项目要做什么（一句话）
   - 哪些事情你绝对不能做（红线）
   - 当前代码骨架是否已搭建（看 backend/ 和 frontend/）

确认理解后，等我下达具体任务。不要主动开始写代码。
```

## 📦 W1 数据准备阶段 · 任务模板

### 任务 1.1：搭建后端骨架

```
请按 CLAUDE.md 模块 B.2 定义的目录结构，搭建 backend 项目骨架：

1. 创建 backend/ 下完整目录树（app/, data/, scripts/, tests/）
2. 初始化 requirements.txt（按 CLAUDE.md 模块 B.1 列出的依赖）
3. 创建 .env.example，列出所有需要的环境变量
4. 创建 app/main.py（FastAPI 入口，含 /api/health 接口）
5. 创建 app/core/config.py（从 .env 加载配置）

完成后告诉我：
- 创建了哪些文件
- 怎么验证项目能跑起来
- 是否有需要我决策的细节
```

### 任务 1.2：搭建前端骨架

```
请按 CLAUDE.md 规范搭建 frontend 项目骨架：

1. 使用 Vite + React + TypeScript 模板初始化
2. 配置 Tailwind CSS
3. 创建 src/pages/ 下三个页面占位组件：Home.tsx, Chat.tsx, Spec.tsx
4. 配置 React Router，路径按 CLAUDE.md
5. 创建 src/lib/api.ts 封装后端 API 调用基础结构

完成后告诉我验证步骤和依赖安装命令。
```

### 任务 1.3：PDF 分块入库脚本

```
任务：实现 backend/scripts/ingest.py，把 data/specs/ 下的 12 部规范 PDF 分块并入库到 Qdrant。

严格遵守 CLAUDE.md 模块 E.1 的分块策略：
- 以"条"为基本单元
- 表格独立 chunk
- 公式独立 chunk
- 每个 chunk 保留完整元数据：spec_code, clause, page, is_mandatory

技术要点：
- 用 PyMuPDF 解析 PDF
- 用 BGE-M3 做 embedding（本地推理）
- Qdrant collection 名 "specs"，向量维度 1024
- 处理时打印进度，避免长时间无反馈

完成后给我：
- 文件路径
- 运行命令
- 怎么验证入库成功（如检索 1 条 query 看是否能召回）
- 估计的运行时间和资源占用
```

### 任务 1.4：实现 RAG Pipeline 主流程

```
任务：实现 backend/app/rag/pipeline.py，封装端到端 RAG 流程。

接口设计：
async def rag_pipeline(query: str, session_id: str) -> AsyncIterator[ChatChunk]:
    # 1. 输入校验
    # 2. 检索（retriever.retrieve）
    # 3. 兜底判断（如检索为空或相关性 < 0.3）
    # 4. 调用 LLM 流式生成
    # 5. 后处理（提取引用、生成追问）
    # 6. yield 多种类型的 ChatChunk

严格遵守 CLAUDE.md：
- 模块 E.2 的检索配置
- 模块 E.3 的生成约束（system prompt 从 prompts.py 读取）
- 模块 E.4 的兜底优先级
- 流式输出 SSE 格式

不要为了"简单"省略中间步骤。每个环节必须实现并有日志。
```

## ⚠️ 常用约束提醒

当 Claude Code 行为偏离时，可以发送这些"纠偏"提示：

### 它擅自换了技术栈
```
等等，CLAUDE.md 模块 B.1 已经锁定了技术栈。请把 <xxx> 改回 <yyy>，并向我说明你为什么想换。
```

### 它编造了规范内容
```
注意 RED LINE 1：不允许编造规范信息。请检查你生成的 <内容> 是否真实来自 chunks。
```

### 它把 Prompt 散落到代码里
```
所有 Prompt 必须统一放在 backend/app/core/prompts.py（CLAUDE.md 模块 F.1）。请把刚才嵌入的 prompt 提取出来。
```

### 它跳过了错误处理
```
CLAUDE.md 模块 C.2 要求外部调用必须有 try/except。请补全错误处理。
```

### 它一次性改了太多文件
```
请暂停。本次任务涉及 <N> 个文件，我希望分步骤来：
先做 <最关键的> 部分，我验证通过后再继续。
```

## 💡 给 Claude Code 的"提效咒语"

下面这些短指令可以经常用：

| 短指令 | 用途 |
|---|---|
| `不要解释，直接给代码` | 当你只想要代码不想看解释 |
| `先列计划，等我确认再执行` | 复杂任务避免跑偏 |
| `按 CLAUDE.md 模块 X 来` | 快速对齐规范 |
| `给最小可运行版本` | 避免过度工程 |
| `这部分不要动` | 保护已 working 的代码 |
| `跑一下并把输出贴给我` | 让它自己验证 |

每天下班前发给 Claude Code：

```
今天到此为止。请帮我做一个简短总结：

1. 今天完成了哪些任务（文件、功能）
2. 当前项目处于什么阶段（参照 W1-W5 计划）
3. 明天起步建议做什么
4. 有没有遗留的 TODO 或 FIXME 需要我关注

不需要写代码，纯文字汇报即可。
```

## ✅ 总结：使用本文件的方式

1. **复制对应场景的 prompt**，粘贴到 Claude Code 对话框
2. **替换 `<...>` 占位符**为你的实际描述
3. **如果 Claude Code 偏离规范**，用"纠偏提示"快速拉回
4. **每个里程碑后**回顾本文件，看是否需要补充新的 prompt 模板

记住：好的 Prompt 比好的代码更影响你的开发效率。
