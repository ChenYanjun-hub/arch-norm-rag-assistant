### Δ 解读：5 条 vs 116 条样本

W5 D2 5 条烟雾的 dim1=60% 确实是抽样噪声（W5 D2 devlog 已预判）— 全量 84.5%，与 regression 的 loose 93.1% 仍有 8.6pp 差距，原因如下：

**关键发现**：quality_eval 用的是 RAG pipeline 输出的 **citations**（LLM 选择后的结果），而 regression 用的是 **retriever search 结果**（前 5 chunk）。LLM 可能只引用 2-3 条 chunk，导致 citations 不足 5 个，loose 命中率自然降低。

这不是 pipeline 退化，而是两个工具测量了不同环节：
- regression = "检索能不能找到"
- quality_eval = "LLM 能不能用对"

## 五、抽样 30 条人工核对 Judge 准确性（W5 D3-3 完成）

**抽样**：15 条 veto + 15 条 non-veto = 30 条
**工具**：`backend/scripts/sample_quality_review.py`
**输出**：`backend/data/eval/quality/sample_review_20260603_134410.md`（1219 行）

### Judge 准确性汇总（30 条人工核对）

| 类型 | 30 条占比 |
|---|---|
| **完全正确** | 18 / 30 = **60.0%** |
| **错判（Judge 自己 hallucinate 错字 / 凭印象判错）** | 4 / 30 = 13.3% |
| **偏严（维度归错 / 截断漏看）** | 3 / 30 = 10.0% |
| **难判（需 full chunks 进一步核对）** | 5 / 30 = 16.7% |

### Judge 系统性偏差（4 类）

#### 1. Judge 自己 hallucinate 错字 ⚠️ **最严重**

| QID | Judge 声称错字 | 实际回答用字 |
|---|---|---|
| Q033 | "原文'游憩'被误写为'游患'" | 回答里就是"游憩"，**Judge 凭印象造错字** |
| Q067 | "原文'宜案用'被改为'宜采用'" | "宜案用" 本身就不是中文词 |
| Q084 | "原文为'路同密度'" | 应为"路网密度"，**Judge 造错字** |

#### 2. PDF OCR 锅被算到 LLM 头上

- Q090 "定牌" — chunks 中 PDF OCR 把 "敷设" / "走廊" 等识别成 "定牌"，**chunks 本身就错**，但 Judge 判 LLM 用词错

#### 3. 维度归错

- Q021 RAG 结论 "280m 符合宜" 是**业务逻辑错**（280 < 300 下限不属"宜"范围）。Judge 应判 dim7 = 0（推导错误），但归到 dim4 用词错

#### 4. chunks 截断漏看

- Q066 JGJ 286-2013 "居住区绿地率不应低于 30%" 是 W5 D2 入库的 spec，chunks 应该有，但 Judge `original_text[:200]` 截断导致漏看

### 校正后的"真实 veto"估算

```
表面 veto: 35 条
扣除明显错杀: 35 × 13.3% ≈ 5 条
扣除偏严: 35 × 10.0% ≈ 3 条
难判按 50% 算: 35 × 16.7% × 0.5 ≈ 3 条

真实 veto ≈ 35 - 5 - 3 - 3 = ~24 条
```

**结论**：即使 Judge 有 ~30% 噪声，真实 veto 仍有 ~24 条，**仍未达到 GREEN 必需的 veto = 0**。

## 六、Judge prompt 修订建议（写入下一版工具）

### 当前 JUDGE_SYSTEM_PROMPT 的 4 个问题

1. **没有"自我警惕 hallucination"约束**：Judge 凭印象造错字
2. **chunks 截 200 字**：长 chunks 内容看不到，假阳性 dim7
3. **维度边界模糊**：业务逻辑错与用词错没区分
4. **没有"chunks 缺失时给 1"的避险**：默认偏严

### 修订建议（W5 D4-D5 实施）

```python
# 新增到 JUDGE_SYSTEM_PROMPT
"""
重要约束（避免 Judge hallucination）：
1. 判 dim4 用词时，只能引用 chunks 实际出现的字符串，不要凭印象判错字
2. 判 dim7 编造时，如 chunks 截断不全（chunks_str 末尾 '...'），给 1 分（避免假阳性）
3. dim4 仅判 '应/不应/宜/不宜/可/不可' 等用词，不判逻辑推导错误
4. 如对某维度不确定，给 1 分（避险），并在 notes 注明"不确定"
"""

# chunks 截断从 200 字 → 500 字
chunks_str = "\n\n".join(
    f"[{i+1}] ...\n{c.get('original_text','')[:500]}"  # 200 → 500
    for i, c in enumerate(chunks[:5])  # 3 → 5
)
```
