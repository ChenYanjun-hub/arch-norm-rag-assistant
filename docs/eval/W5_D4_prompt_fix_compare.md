# W5 D4 · Prompt 加固前后对比（D3 baseline vs D4 修订）

**RAG 配置**：Combo E（multi_query=on + reranker=on + hybrid=off）— 两次评测相同
**评测集**：`eval_set_v1_150_v4_5.csv`（116 有效条目）— 两次评测相同
**唯一变量**：`SYSTEM_PROMPT_MAIN` + pipeline 新增 dangling 监控（不影响 RAG 输出）
**日期**：2026-06-03（W5 D4）
**核心结论**：✅ **Prompt 修订有效，综合分 +1.5 / 真实 veto -3（校正 API err 噪声后）**

## 一、改动摘要

### Prompt 改动（`backend/app/core/prompts.py`）

新增"W5 D4 防编造硬约束"4 条：
1. [N] 引用脚标范围严格 ≤ 片段数
2. 补充说明禁止越界（任何"补充说明/另注/备注"小节不得超出片段）
3. 强制性条文标识只信片段元数据（不自行推断）
4. 不联想其他规范（联想必须由用户主动问）

第 4 条规则末尾加："**[N] 的 N 范围严格限定在用户消息提供的片段编号内**"。

### Pipeline 改动（`backend/app/rag/pipeline.py`）

- 流式末尾扫 `[N]` 引用，N > len(chunks) 计入 `dangling_count`
- 新增 `metadata` 事件携带 `{dangling_count, n_citations_in_answer, n_chunks_available}`
- 越界时 logger.warning 输出（便于 batch eval 后 grep）

## 二、表面 vs 校正后对比 ⚠️ 关键

### 表面数字（含 API err 噪声）

| 指标 | D3 | D4 表面 | Δ 表面 |
|---|---|---|---|
| 综合得分 | 86.0 | 83.4 | **-2.6** ❌ |
| veto 总数 | 35 | 38 | **+3** ❌ |

**首次解读**：触发 CLAUDE.md F.2 "评测分下降则回滚"。

### 深入分析：D4 的 6 条 API err 是元凶

D4 跑批中 DeepSeek API 6 次连接失败（5.2% 错误率，D3 = 0%）：

| 失败 QID | 状态 |
|---|---|
| Q002, Q005, Q006, Q007, Q009 | 5 条 D3 OK → D4 因 API err 被工具判 4 维全 0 → 伪 veto |
| Q003 | D3 本就 veto，D4 API err（不改变结论）|

`run_quality_eval.py` 的 API err 处理逻辑：
```python
if "error" in judge_result:
    d3 = d4 = d5 = d7 = 0  # 所有维度判 0
    notes = f"judge_error: {...}"
```

→ 5 条伪 veto 拉低 4 个维度的平均分 + 增加 veto 计数。

### 校正后真实对比（去除 API err）

| 指标 | D3 (n=116) | D4 净 (n=110 排 API err) | Δ |
|---|---|---|---|
| **综合得分** | **86.0** | **87.5** | **+1.5** ✅ |
| **真实 veto** | 35 (30.2%) | 32 (29.1%) | **-3 条** ✅ |
| dim1 检索召回 (loose) | 84.5% | 86.4% | +1.9pp ✅ |
| dim2 精确条款 (strict) | 67.2% | 69.1% | +1.9pp ✅ |
| **dim3 引用准确** | 96.6% | **99.1%** | **+2.5pp** ✅ |
| dim4 原文用词 ★ | 83.6% | 83.6% | 持平 ⚪ |
| **dim5 数字精确 ★** | 93.1% | **96.4%** | **+3.3pp** ✅ |
| dim7 不编造 ★ | 78.4% | 78.2% | -0.2pp ⚪ |

**结论**：
- ✅ Prompt 修订**整体有效**，所有维度至少持平或改善
- ✅ 4 条新约束的"直接命中维度"显著改善：
  - dim3（引用准确）+2.5pp — [N] 范围约束生效
  - dim5（数字精确）+3.3pp — 不联想 + 不补充的间接受益
- ⚪ dim4（用词）/ dim7（编造）几乎没动 — 编造是顽疾，prompt 单点不够

## 三、Q-by-Q 翻转分析

### 真实新触发 veto（D3 OK → D4 触发，10 条 — 排除 5 API err）

`Q011, Q027, Q046, Q047, Q057, Q068, Q098, Q119, Q121, Q132`

## 四、Dangling Citations 监控数据

D4 跑批中 logger.warning 命中 `[N]` 越界引用号警告：

```bash
grep -c "dangling_citations" backend/data/eval/quality/_w5d4_run.log
# 1 条（含已知 false positive: "教职成[2010]12号"）
```

⚠️ **已知 regex 偏差**：`\[(\d+)\]` 会误匹配年号脚标（如 `[2010]`）。

**修复方向（W5 D5）**：改为 `\[(\d{1,2})\]` 仅匹配 1-2 位数字。

## 五、按编造模式的修复率

基于 25 条 D3 dim7=0 的 4 类编造模式：

| 编造模式 | D3 触发条数 | D4 触发条数 | 修复率 |
|---|---|---|---|
| 编造引用号 [4][5][6] | ~4 | ~1 | ~75% ✅ |
| 补充说明区编造 | ~5 | ~5 | ~0% ⚪ |
| 编造"强制性条文"标签 | ~3 | ~2 | ~33% |
| 编造跨规范引用 | ~1 | ~1 | ~0% |

**关键观察**：**约束 1（[N] 范围）+ 约束 4（不联想）效果好**，**约束 2（不补充）效果差**。

可能原因：LLM 仍然有"完整回答"的强训练倾向，"补充说明"小节是难以根除的输出习惯。需要更强的反向训练（few-shot 反面例子）或后处理。

## 十、AIPM 启示候选

- **启示 50 候选 · 评测工具的故障是评测结论的隐藏变量**：D4 看似 -2.6 分实际 +1.5 分，差距全在 5 条 API err 被工具误判 0。教训：评测工具的失败处理必须保守（跳过而非判 0）。

- **启示 52 候选 · "补充说明"是 LLM 的训练惯性**：约束 2 修复率 0% — LLM 对"完整回答"的训练倾向比 prompt 约束更强，需要更强力的手段（如后处理 strip "补充说明" / "另注" 节）。
