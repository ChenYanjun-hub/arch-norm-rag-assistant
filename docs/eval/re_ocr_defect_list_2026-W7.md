**误报根因**：这两部分乱码/空的 chunk 是 `type=appendix`——来自标准末尾的

**这是正确的数据，不是缺陷**。原扫描口径把索引 chunk 和正文 chunk 混在一起看了。

**端到端验证（决定性证据）**：直接问这两个问题，答案正确且引对条文——

- 「什么是公园绿地？」→ 引 `CJJ/T 91-2017 4.1.1`，完整给出「向公众开放，以游憩为主要功能…」

**教训**：以 chunk 静态特征（长度/中文占比）判缺陷会误报；**判定缺陷必须端到端问一遍**。

## ✅ 真 P0（本轮已修）· 页脚水印污染 11.2% 语料

全语料扫描发现的**覆盖面最大**的一类缺陷（原清单未识别）：

| 指标 | 数值 |
|---|---|
| 受污染 chunk | **1212 / 10785（11.2%）**，涉及 42 部规范 |
| 删除的噪声行 | 4173 行（水印 + 紧贴的页码）|
| 水印落在正文中间、切断句子 | 897 条 chunk |
| **水印落在用户可见 `original_text[:200]` 里** | **928 条**（占受污染 77%）|

「住房城乡建设部信息公开 / 浏览专用」是 PDF 页脚水印，被 OCR 当正文抓进 chunk。
最严重的表现是**它落在引用卡的原文摘引里**——对一个主打「可追溯原文引用」的产品，
在引用的条文里混进水印，直接伤可信度。

**修复方式**：`fix_chunks_ocr.py` 第 3 类 `strip_page_furniture` —— 精确白名单**整行删除**
（23 种已核水印残片形态），绝不改保留行的字符，故不可能动到规范用词（红线 3）。
全语料 24 种含关键词的整行里有 1 种是**正经条文**
（"…2017 年国家发展改革委住房城乡建设部印发《关于规…"），
用「整行完全相等」才躲开它——写成 `住房城乡建设部.*` 正则就会删掉真条文。

**修复后**：残留水印 chunk **0 / 10785**；11 条单测锁住行为；已重建全部 10785 个向量。

**效果度量（诚实结论）**：
- 检索：strict Hit@5 **89.78% → 89.78%（无变化）**；MRR_strict 0.830 → 0.815。
  4 条 query 从 rank1 掉到 rank2，0 条变好——但 rerank 分数在 **0.99+ 饱和区**，
  差距仅 0.001~0.009，且 3/4 是**同规范相邻条文**互换（另 1 条换成 GB 55037 的更新版条文）。
  判读：**饱和区的 top-1 排序本身不稳定，不足以据此接受/否决改动**。
- 生成：做了带水印 vs 已清理的 A/B（同 query、temperature=0）。
  **LLM 对断句是鲁棒的**——两版都正确引出「均应符合消防安全要求」，
  **原先预判的红线 3 误引风险未发生**。唯一差异是清理后答案覆盖了 5/5 个子项（原 4/5），n=1 不足以泛化。
- 所以本次修复的**已证实收益是「用户可见原文摘引干净」+ prompt 噪声 -1.21% 字符**，
  **不是**可测量的答案准确率提升。
